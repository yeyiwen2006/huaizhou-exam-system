# 服务器内部自动备份与归档清理

自动维护由 `Exam.Management` 承载，不依赖 Windows 计划任务、Python 或客户端在线，不使用固定的凌晨执行时间。

部署时在服务器管理配置中加入以下设置。`StateDirectory` 必须填写该节点自己的绝对路径，并由服务账号读写。主备节点分别配置，只有数据库和应用均确认自己为活动主节点时才执行。

```json
{
  "Backup": {
    "Automatic": {
      "Enabled": true,
      "RetentionDays": 7,
      "IntervalHours": 24,
      "MinimumFreeBytes": 10737418240,
      "StateDirectory": "D:/ExamDeployment/backup-maintenance"
    }
  }
}
```

服务启动 30 秒后检查最近成功的自动备份；距上次备份不足 24 小时不会重复备份。已到期则在线备份，不停止业务服务。检查循环每 5 分钟唤醒，失败最多每小时重试一次；不会在学生请求中执行维护，也不会每次轮询都扫描备份或校验文件。

## 保留和清理

- 复用现有应用恢复格式，包含整个数据库、版本化资源和受保护配置。完成后检查文件目录、长度及恢复所需 WAL，不额外进行全盘哈希扫描。
- 保留最近 7 天的备份，以及 7 天起点之前最近的一份基础备份；至少保留两份已完成备份。
- 连续恢复需要从最早保留备份开始的完整归档。清理边界还受所有复制槽及备机回放位置约束，绝不按文件修改时间直接删除 WAL。
- 备机断开、复制槽失效、归档链缺失、备份失败、恢复或重建目录非空、角色变化、备份跨越时间线时暂停清理。时间线切换后需核对恢复链。
- 只删除本功能创建且完成校验的过期自动备份，以及安全边界之前、同一时间线的 WAL。时间线历史、备份历史小文件、手动备份、启动引用的初始备份和未知文件保留。
- 单独保留的旧手动备份仍可恢复到备份完成时刻；它们不将连续按时间恢复的 7 天窗口无限延长。
- 可用空间不足 10 GiB 时暂停备份并报告。失败半成品保留排查，不会不断创建新的失败副本，也不会为腾空间删除仍需使用的恢复材料。
- 状态覆盖写入 `StateDirectory/status.json`，不会无限追加维护日志。`completed` 表示本轮完成；`paused` 附带中文原因，原有备份与必要归档仍保留。

初次启用不足 7 天时，可恢复时间从最早有效备份开始计算。归档周期维持部署现有配置，不改变同步提交、主备确认或业务恢复流程。不删除活动数据库的 `pg_wal`。

恢复时，使用自动备份目录中 `exam-backup.json` 的 `backupId`，走现有服务器管理恢复流程。备份位于本机磁盘，磁盘损坏的灾难恢复仍需要异机备份；主备同步继续提供实时的另一台机器副本。

## 集成测试隔离

```powershell
python eng/testing/run_isolated_postgres.py
```

只运行相关测试时添加 `--filter FullyQualifiedName~测试类名`。每次创建临时 PostgreSQL 18 实例，使用随机回环端口和独立密码，关闭归档，结束或正常中断后停止进程并删除该次临时目录。不会继承主备连接变量。

测试夹具在创建数据库前拒绝业务或主备实例。现有 `run_checks.py --postgres-bin ...` 和物理恢复专用入口仍可使用，明确标识的临时实例允许执行归档测试。GitHub CI 独立 PostgreSQL 容器不受影响。
