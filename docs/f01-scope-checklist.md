## 与相邻任务的边界

- **F01**：独立宿主、受控服务、配置、诊断、备份和隔离恢复运行闭环、共用 API/CLI 处理器及本模块开发期测试。已有 A02—A06 成果复用，不重写身份、答卷、计分或领域状态机。
- **F02**：复制确认、旧主隔离、备库提升、权威代次更新、单机应急、旧主重建/恢复同步。F01 保留所需检查和共享入口，不实现未经确认的提升或绕过业务门禁。
- **F03/F04**：学生端可信切主及现有考务 GUI 管理接入。F01 提供可消费接口/处理器和独立连接，页面布局/导航等不是 F01 后端完成百分比的分母。
- **F05**：产品部署、WAL 归档/重建/监测工具。F01 必须验证备份恢复与这些工具/材料的衔接，不能将自己缺少的恢复核对归给 F05 后忽略。
- **E01/E04**：公共 CLI 注册、CI/测试设施及候选包；F 提供具体业务处理器并做模块测试。没有注册的处理器只能算已交接口，不能算用户命令已上线。
- **T01/T02/T03**：固定候选的全项目/现场验收及最终交付。开发期间适用的真实文件、数据库、接口、恢复及回归仍必须实跑，生产闭环须在 T01 前完成。

备份启动检查已补入生产管理宿主：按部署指定目录/标识运行清单、资源/受保护材料摘要及 PostgreSQL 工具校验，失败阻止启动；仍不代表备份新鲜度、服务器归属、连续 WAL 或实际解锁已经核实。生产恢复切换的具体调用、持久阶段及需 A 确认的权限/数据差异见 [实施方案](f01-recovery-switch-proposal.md)。

## 接续优先顺序

1. 在当前集中分支完成可独立推进的生产注册故障诊断、响应超时及操作记录读取边界修正与回归；补非秘密部署模板，不等待 Windows。
2. 明确生产恢复的调用与边界：由哪一受控宿主启动隔离 PostgreSQL、如何固定并证明目标身份/隔离、怎样核对旧备份后的数据缺口、何时推进原请求的持久阶段、怎样切换秘密连接配置及失败回退。ADR 已授权恢复工作，但没有给出上述公共切换协议；需 A 对具体差异确认。不能自行新增管理操作/迁移、用普通配置改写或删除 Staged 记录绕过。
3. 把现有恢复探针及业务收卷入口接到该目标，补编号接续、题包/解锁、事件/定时、原回执、剩余收卷及计分一致性的产品模块验证。已有合成物理演练只覆盖其中部分，不宣称恢复后计分或完整领域事件运行已验收。
4. E 接现有 CLI；Windows 实跑管理/业务 SCM、TLS/私钥/ACL、配置与请求重启、完整解决方案及适用故障回归。新账户/主机、WAL 连续恢复与真实设备/双机证据按 F05/T01/T02 协作，但不提前关闭 F01。

本清单不授权越过 ADR 边界，不创建新的分支/细碎 PR，也不修改仓库 AGENTS.md。
