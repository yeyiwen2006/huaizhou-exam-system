# 单节点学生登录与公网入口修复

整理来源：最新主分支 `63d13c3`（包含 `cd31898` 主备状态修复）的实际登录、证书、设备登记和发布路径，以及隔离的合成回归测试。

脱敏声明：本文及部署样例不包含真实考生、现场地址、凭据或证书内容。

## 问题与修复

需求是任一健康活动节点独立可用时，学生能够登录，不依赖另一节点在线。备机需先按既有隔离与持久确认流程接管；客户端不会提升只读备库。

内网证书指纹配置与公网 HTTPS 代理证书不同。携带内网 `certificateSha256` 的客户端直接输入代理域名，会在 TLS 阶段被拒绝，与备机是否在线无直接因果关系。公网连接应使用部署方明确配置的节点映射与标准证书链校验，不能通过忽略证书错误解决。

原 `publicEndpoints` 强制配置两个入口，并要求它们覆盖返回或保存的全部节点。这使只部署一个公网入口的场景无法使用。现在允许一至两个入口，仅替换被明确配置的节点路由，保留其余节点的原地址或已登记公网路由。

迁移仍校验逻辑服务器、节点和源地址，保留设备标识、凭据、编号、代次及节点证书指纹。所选入口不对应已登记可信节点时拒绝迁移。登录成功路径不探测另一节点，不新增数据库查询或跨机确认。

登录页的证书错误提示说明需要核对连接地址及公网部署配置。单端与统一发布脚本均携带 [单入口模板](../deploy/student/server.public.single.example.json)，使用步骤见 [学生端部署说明](../deploy/student/README.md#通过公网-https-入口连接主备节点)。部署配置更改后须重启客户端，原设备登记与答卷继续保留。

## 验证

按照仓库约定，测试源码仅保存在本地 `tests/`，不加入 Git。

修复前，单入口专项 13 个用例中 11 个失败，拒绝原因为配置要求两个节点。修复后补充已有主机登记在接管后备机登录的场景，并以独立的 HTTPS 回环服务器验证真实 TLS：主机单独运行、已接管备机单独运行、服务端返回一个或两个节点、正确证书及错误证书均被覆盖。继续链接适用的既有设备身份、HTTP 与故障转移回归后，共 72 项通过。原身份测试项目有旧登录签名导致编译失败，未将整个旧项目列为通过。

TLS 回环服务器使用隔离的合成证书及临时目录，不向 Windows 证书库写入信任根。此环境的旧 Schannel 服务端测试夹具无法导入临时私钥，因此改用 Python 标准库承接测试服务端 TLS；客户端仍是生产 `HttpStudentApi` 与 Windows TLS 栈，未替换客户端验证逻辑。

已执行的主要命令：

```powershell
dotnet test tests/Unit/Exam.SingleNodeLoginTests/Exam.SingleNodeLoginTests.csproj -c Release
dotnet restore Huaizhou.ExamSystem.sln --locked-mode
dotnet build Huaizhou.ExamSystem.sln -c Release --no-restore
```

完整解决方案 Release 构建通过，零警告、零错误。测试使用合成登录响应；未使用真实考生资料执行登录，也不等于两台现场数据库完成了故障接管验收。

## 与主备状态修复的关系

本修复建立在 `63d13c3` 之上，保留上游的选项显示修复、备机只读状态检查、轻量管理检测及负重放差值显示修正。它修复学生端的入口配置限制，不改变服务端的活动节点、隔离、确认边界或业务写入门禁。主库新连接超时仍需按 TCP、TLS、认证和 SQL 阶段定位，不能依据学生端证书错误推断数据库连接已耗尽。
