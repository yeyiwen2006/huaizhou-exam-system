# C04 考试监测与学生状态接线

对应 [C01–C04 剩余业务实现与接线 #46](https://github.com/yeyiwen2006/huaizhou-exam-system/issues/46)，需求依据为 requirements.md 的“实时监测与回收”、设备身份、时间和持久化要求。界面样例和测试数据均为合成数据。

## 监测数据

考务端使用 GET /api/v1/exams/{examId}/monitoring。姓名、班级、准考证号、学生端编号、试场、业务状态、连接状态、页面、当前题号和答案、版本与下载结果、最后通信、指令确认、冲突设备、失焦及回收信息，来自服务器同一次可重复读事务。

正式题号由服务器的已发布试卷结构提供，不再把内部题目标识直接显示为题号。最终答案优先使用持久化答卷；当前设备状态须匹配该参试的考生会话。私人标记不进入监测接口。

只有最终持久化回执计入已回收。离线不改变候考、作答、已交卷等业务状态。切出窗口时立即显示“正在答题（已切出）”，结束的失焦时段继续通过原持久化发件箱上报；本地保存失败单独显示，不能冒充已保存。

## 学生端上报

生产入口接入已有 /student/presence/open 和 /student/presence。每个进程建立一次租约，运行内序号递增。重试打开连接沿用原请求号，替换掉的旧进程不重新抢占租约。

页面切换、登录会话、答题状态和窗口切出触发上报；下载变化每 500 毫秒检查一次；不变状态每 60 秒完整补报。请求串行执行，退出系统会尝试报告断开。状态回执与答案保存回执分开，前者不能证明后者成功。

## 考务操作

- 前台监测每 750 毫秒读取一次；一轮结束前不启动下一轮自动读取。正常状态下给学生端检测和网络处理留出时间，不能把刷新周期本身等同于端到端延迟验收。
- 可组合筛选试场、学生端编号、姓名、班级、准考证号及未回收状态，人数仍采用全场实际名单。
- 自动刷新保留考生选择、有效指令和输入中的裁决原因。指令、冲突设备或授权版本变化时清除失效选择，要求重新核对。迟到的旧快照不能覆盖新状态。
- 自动读取失败保留上次可信结果并标明陈旧；手动读取发生传输失败清空列表。非法快照整体拒绝。
- 收齐记录每秒读取，不依赖监测页是否在前台。按服务器、考试、名单版本去重；多个版本分别排队提醒，零参试不提醒。
- 补传使用仍有效的结束指令，服务器在持久确认后实际推送。END 已确认但答卷未回收时仍可请求补传原固定答卷；已经回收或授权失效时拒绝。重发不重新开放答题，不清除原指令确认。

## 接口与边界

沿用考务登录和设备凭据两个权限边界，不把考务账号接到学生专用实时通道。公共契约仅新增可空 CurrentQuestionNo；页面状态增加切出与本地保存失败，无数据库迁移。详见 [考务接口](administration-api.md)。

本地检查覆盖单元、真实 PostgreSQL、HTTP、持久确认失败、旧状态与授权、重复结束指令、WPF 绑定及合成截图。命令和实际结果见 [PR #122 审查记录](reviews/pr122-review-20261005.md)。多机网络、300 人现场时延及主备物理恢复仍须按 T01/T02 进行现场验收；本 PR 的模块检查不替代该验收。#46 不因本次监测改动自动关闭。
