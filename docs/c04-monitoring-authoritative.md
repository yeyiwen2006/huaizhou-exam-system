# C04 监测页接通权威状态（2026-10-05）

对应 [C01–C04 剩余业务实现与接线 #46](https://github.com/yeyiwen2006/huaizhou-exam-system/issues/46)，
落实 `docs/reviews/ui-requirements-c-20261002.md` 的第 9、10、11、13、14 项与第 17 项中属于监测页的部分。
需求依据：`requirements.md` 第 25、35、176–184 行。

## 数据来源

监测页不再由考务端拼接多个来源，也不再使用占位值：

- 参试列表、姓名/班级/准考证号、学生端编号、试场、业务状态、连接状态、当前页面、题号及已选答案、
  试卷版本与更新结果、最后通信时间、指令与确认情况、失焦汇总、修订复核、答卷回收状态、回收人数与
  未回收名单，全部来自**一次** `GET /api/v1/exams/{examId}/monitoring` 的权威聚合快照
  （服务端在同一 PostgreSQL MVCC 快照内读取名册、设备、进度、在线、答案、回执、失焦、冲突和有效指令）。
- 答卷收齐记录仍按**历史补取**保留：打开监测页时每 20 秒按名单版本游标补取，用于重开页面与断线恢复，
  不承担实时监测职责。
- 本页整取快照、不带服务端筛选参数，筛选在界面内按现场使用的信息完成。

## 界面行为

- **业务状态与连接状态分列显示**：业务状态取候考／作答中／已交卷；连接状态取在线／离线／恢复中，
  没有有效通信记录时显示“未登录”。离线只改变连接状态，不改变业务状态；
  离线判定（明确断开或被判定超过 135 秒无有效通信）由服务端策略给出。
- **未持久保存不显示已回收**：回收状态直接取服务端结果（已回收／回收中／未回收），
  只有带持久化回执的参试记录才会显示为已回收。
- **自动刷新**：监测页在前台且连接就绪时**每 2 秒**自动读取权威快照，进入页面立即读一次；
  刷新失败**保留上一次可信结果**，失败原因与读取时间写在专门的**数据新鲜度提示**（`RefreshNote`）里：
  状态栏只放考务的操作反馈与手动刷新汇总，自动刷新无论失败还是恢复都不覆盖它；
  被拒绝的快照同样只写新鲜度提示，首次读到数据时把“请点击刷新”的占位说明换成计数汇总。
  操作者选中的行、指令与对照设备在刷新后按标识选回新实例，不会变空，也不会使在途请求失效。
  刷新周期可注入，实现集中在 `MonitoringViewModel` 的刷新循环内，便于后续替换为推送通道。
- **筛选**：试场、学生端编号、姓名、班级、准考证号可组合，另有“只看未回收”和一键清除筛选；
  试场选项来自当前考试的权威数据。
- **回收统计与未回收名单**：显示实际参试人数、已回收份数、未回收份数，并提供未回收名单；
  在未回收名单中选中考生后可**请求补传**——只重发该考生仍可重发的结束指令，
  已确认或已拒绝的指令不会重复发送。
- **冲突对照**：处理多设备冲突前先列出两台设备的学生端编号、试场、是否当前授权、连接状态、
  最后通信时间和答题进度，选中要保留的设备后确认；原因写入操作记录。
- **不再手填内部标识**：重发指令改为按名称选择该考生可重发的权威指令（开始答题／结束答题等），
  收齐弹窗显示考试名称，监测列表不显示参试记录、设备、事件等内部标识。

## 边界校验

`AdminApiClient.GetMonitoringSnapshotAsync` 在**返回前**完成校验，任一不成立即整体拒绝
（`INVALID_RESPONSE`），不把半份状态交给界面：

- 考试标识、版本向量、读取时间、考试状态合法；
- 参试人数、已回收人数与两份名单互相自洽，未回收名单是参试列表的子集且不带回执；
- 每名考生的身份字段非空、枚举已定义、版本不越界、答案/指令/冲突设备结构合法；
- 同一名考生在一场考试内不会出现两条参试记录；回收状态与持久化回执一致。

快照被拒绝时**保留上一次可信结果**并提示；传输失败（网络、HTTP 错误）时清空列表，避免显示过期状态。
快照被拒绝、传输失败与考试/服务器切换都会使迟到的响应失效。
