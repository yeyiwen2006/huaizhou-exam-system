## 修正内容

正式数据库服务不再固定关闭归档。`BuildPostgresServiceCommand` 与原生回归共用 `BuildPostgresRuntimeArguments`，固定 `archive_mode=on`、空 `archive_library`、受保护脚本及归档目录，并保持 `fsync`、完整页写入和禁用未审查恢复/清理/预加载钩子。管理宿主接入两项归档部署配置，检查实际命令与主库归档回执；缺失或不符时阻断，不能用静默关闭归档继续运行。临时隔离恢复服务保持原来的 `archive_mode=off` 和隔离约束。

原生测试发现 Windows 中文路径与 PostgreSQL 原生代码页不一致：生成器改为无损原生配置编码，CA 统一导出公开 PEM；实际归档命令按原生字节核对，避免将路径错误解码为数据库 UTF-8。路径限制包括附加数据流、命令分隔符、链接/联接及目录互相包含。

基础备份显式使用 `--no-clean`，拒绝未经映射的外部表空间，失败保留部分数据和复制槽。初始化将备用应用名写入 `pg_basebackup -R` 的自动配置，避免其覆盖片段后变成异步的 `walreceiver`。生成器、初始化与自检可指定一致的备用应用名和复制槽。

Windows 归档回调的复制与摘要读取允许 PostgreSQL 持有 WAL 的读写句柄，同时继续核对内容、持久刷新和无覆盖发布。不同内容的同名归档不覆盖。自检禁止 URI 查询参数覆盖已验证的端点或 TLS；两侧均核对持久化配置。PowerShell 5.1 子检查失败仍输出结构化失败报告，不能中途丢失结果或显示就绪。
