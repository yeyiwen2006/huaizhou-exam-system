## 接口与恢复约定

D04 `GradingCoordinator` 的成功数是处理成功的任务数，不是独立考生人数。同一答卷可能存在旧目标和新目标两个任务，但结果表只有一行；D05 必须从全部最终答卷及实际结果计算范围和人数。

`RecalculationScheduler` 改用独立的重算队列接口，所有仓库调用方和测试替身已同步。`PostgresRecalculationQueue` 验证考试归属，避免为另一场考试的答卷排队；并发恢复同一缺失成绩只重新打开一次任务。未更改 A05 事务收卷、原答案、回执和普通去重规则。

本 PR 不新增数据库迁移，依赖已合并 PR #56 的 `grading_results` 和 `lease_expires_at`。上线前先应用所需迁移，停止不兼容的旧计分消费者；历史成绩缺失恢复走重算队列，不修改 A05 最终答案或原始回执。参考 `docs/reviews/pr56-d04-persistence-20260925.md` 的迁移和恢复说明。

## 不应混淆的交付边界

这里交付的是规则版本重算规划、数据库范围读取、恢复调度及与 D04/A05 的接口验证，不是完整生产报表发布实现。调用方必须从 A06 获取当前已发布版本，并经过现有主备写门；本次仅依据已读成绩检测到的过期目标/版本冲突进行阻断，不替代 A06 当前版本校验。

`GradingReadiness` 是范围快照，不是可以跨请求缓存的查看/导出授权。生产报表仍须在访问时核对当前已发布版本、当前全部最终答卷集合及结果一致性；新的规则或补收都会使旧快照过期。不得把这一判定当作 A06 首次发布规则的前置条件，否则会形成“先有规则才能计分、先计分才能发布规则”的循环。

未在本次 PR 中自动注册生产后台循环、GUI/CLI、报表门、主备故障恢复流程；未执行真实 TeX 编译、300 客户端压力或主备断电演练。因此不把这两个 PR 的合并等同于 D04/D05 全部产品验收或整个考试系统已达交付标准。
