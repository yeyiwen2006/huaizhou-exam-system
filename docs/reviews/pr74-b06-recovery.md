## 已修正的阻塞问题

### 题包、答案版本和恢复意图

原更新路径在保存控制文件前替换明文并清零旧包；控制文件失败后无法满足旧版可恢复要求。协调器又在答案版本结转前发送 `Applied`，可能对外报告实际尚未持久完成的更新。

现在候选包先完成身份、版本、清单与稳定结构核对。更新意图先写入受保护控制日志，随后 SQLite 同一事务保存新版本答案与待同步快照，成功后才发布内存版本并销毁旧明文。答案与包发布期间禁止同步服务把短暂版本交接误判为永久身份冲突。结构核对包含题号、题型、选项集合与顺序、科目题组及弃权约定，不仅检查已有答案是否碰巧仍合法。

SQLite 返回失败时先回读：已提交的原请求可继续发布；确实未提交则保留旧包，暂停新增作答并沿原更新重试；结果无法核对则保留意图和数据库，禁止猜测或以旧状态覆盖。重启通过答案版本、身份和快照请求标识核对未整理的更新意图，不凭本地恢复记录授予在线授权。

为兼容原启动流程，仅在存在更新意图时提前读取答案与快照。开发中的第一次整组回归发现无条件提前读取会阻塞既有“恢复读取期间到达终态”夹具；修正调用顺序后，原有两个断言均通过，没有删除或跳过。

### 撤权、结束和固定答卷

原新版解锁拒绝即使带 `AuthorizationRevoked`，也可能仍保留旧包可访问。修正后该错误进入停用路径，已验证设备裁决同步撤销访问；答案写入和包处理不等待慢下载完成才停止。END、撤权和固定交卷优先于在线更新，旧答案保留但不恢复新增作答。运行时清理的信号量在异常路径也保证释放。

“任一步失败仍可继续旧版答题”的原说明已撤回：下载或无效候选包可以保留旧版，而权限变化必须停止，无法确认持久结果时必须阻止继续写入。

### 更新日志、事件和回执

原协调器接受未验证消息，维护只在内存中的待办及确认列表，并在完成时清空整个队列，存在丢失新事件及重启任务的风险。现以管理器已验证的持久日志为唯一任务来源；空闲循环不销毁，新事件使用同一唤醒机制。

准备、确认和结果重试保留稳定请求；已应用的重复指令重放 `Applied` 而非退回 `Received`。结果返回完整匹配后才记作确认，实际版本不匹配、外场及未知事件被拒绝。错误回执保留原请求继续补发，不让 `InvalidDataException` 逃逸终止循环。旧版本结果回执丢失不会阻塞更高版本下载和提交，也不会把旧结果改写为新版本。

### 正式进度接口衔接

原复焦逻辑使用新请求 ID 发送未递增的答案版本，正式 `SubmissionService` 和存储版本约束会拒绝，学生同步因此进入 `Blocked`。原测试的模拟服务未实现该版本约束。

新增真实业务服务和参考存储接线用例复现后，撤回服务端未消费的失焦契约字段；焦点变化只触发原答案快照的幂等核对，不制造同版本新写入。累计次数包括进行中的失焦，持续时间使用单调时钟，回执等待期间新发生的事件不被当作已处理。界面明确区分本机会话统计与服务器留痕。完整失焦事件持久化/补报属于未完成功能，而不是本次“已修复的上报服务”。

### 本地迁移、复核与退出

SQLite 迁移先验证数据库身份和旧结构再修改；不同数据库的侧文件不再导致先升级后拒绝。数据库已提交 v2 而身份文件仍为 v1 时，验证匹配后可继续完成侧文件写入。保存侧文件使用刷盘及替换，不重建缺失或损坏的答案库。

实际安装与待复核版本可恢复；首次确认保留，旧版确认不能确认后来安装的新版。界面改为阅读修订内容后由按钮确认，取消安装后立刻弹出“已复核”对话框的做法。撤权提示不再保证未确认上传的答案已经在服务器。等待页卸载后不新开请求，正常退出先释放快捷键钩子和置顶限制。

快捷键判定将真实 Ctrl 状态与事件标志分开；`0x02` 不再作为 Ctrl。钩子安装失败明确呈现，不宣称防护正常。本轮没有真实按键与普通账户手动验收。

## 测试稳定性修正

原远端 CI 的服务状态序列测试曾在一秒等待预算内超时；原本地负载契约测试也有失败。两个测试将逻辑断言与测试宿主的调度、冷启动耗时耦合。

`WindowsServiceBusinessHost` 与负载运行器增加可注入单调时钟，默认仍为系统时钟。服务状态序列测试使用确定性时钟，保留未启动超时断言，增加注入时钟的截止测试。合成 HTTP 契约测试不再把冷启动当作真实容量测量；新增 500、501、2001 毫秒实例核对原阈值分别通过、失败、失败。没有改变生产服务默认 60 秒等待、负载 P95/P99/最大值阈值或实际 CLI 的计时方式。
