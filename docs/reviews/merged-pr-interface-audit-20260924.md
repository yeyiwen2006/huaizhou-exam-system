## 已修复的问题

### 解锁成功不等于可创建答题会话

原 B02 正确认证了密文和解锁材料，但 `StudentExamRuntime` 没有解释实际包内容。只要解密成功，即使明文不是 ZIP，或清单属于另一场考试，也会创建空的 SQLite 答题状态。

新增 `StudentPaperDefinition`，由运行时在创建会话前读取认证后的内存载荷，核对清单所属考试、D01 结构/语义、必需 PDF、资源根和显示文件头。拒绝重复路径、大小写碰撞、越界路径、无效 Windows 文件名、缺失/不支持的清单和超限展开内容。读取不解压到磁盘，得到的题目标识、选项、题型与允许弃答配置保存在不可变目录中。

目录解析放在工作线程；结束或撤权可能在解析期间清除载荷，因此创建会话前还要复核载荷引用和解锁状态。已有 SQLite 恢复期间的结束/撤权检查继续保留。

### B04 的稀疏冻结答卷不能交给 D04

原 B04 以空字典开始，只保存被操作过的题。D04 明确要求每题有记录，不能将漏传与未作答混为一谈。新会话现在按已校验目录一次性持久保存全部题目的 `Empty`，随后选择、标记、导航和冻结仍经过原来的串行事务路径。

有旧记录时不自动补齐。发现缺题、额外题目、非法答案、未知标记/导航或身份不符，停止恢复并保留原记录。已经固定的旧答卷也不会改写；其后续收卷/计分处理仍需按原证据和版本核查，不能静默修补。

运行时始终传入目录。`AnswerSession` 原构造调用保留给既有低层存储测试与兼容调用；它单独使用时不提供题目完整性保证，生产答题流程不得绕开运行时另建不绑定目录的会话。

### 本地作答约束与计分约束不一致

原本地接口只检查答案结构，可以保存未知题号、未知选项、单项题多选和未启用的弃答。新目录将题组的 `type` 与 `allowAbstain` 传入本地校验；非法操作在增加答案版本或写入 SQLite 前拒绝。未作答仍是 `Empty`，弃答仍是 `Abstain`，不改变既有 JSON 枚举名称。

A05 的 `SubmissionPolicy` 另补 `Enum.IsDefined`。共享 JSON 转换器允许数字枚举，原先 `kind=-1` 或 `999`、空选项数组能被接受，之后却无法计分；现在进度和最终提交均返回 `InvalidRequest`，不写入、不安排计分。正常三种作答类型保持兼容。

## 契约与兼容性

`StudentPackageLayout` 固定现有 `questions/<源文件去掉扩展名>.pdf` 映射。清单仍为 `manifest.json`，不新增坐标字段、不改变 HEXAMPKG v2 密文格式或任何网络 DTO。

清单上限继续为 8 MiB，文件展开内容合计继续为 256 MiB；本次增加每包最多 10000 个 ZIP 文件，生产端和消费端同时执行。重新序列化后的清单也检查 8 MiB，避免 UTF-8 文本经 JSON 转义后超过学生端限制。资源根继续沿用 D01 的规范化语义，包括 `.`；读写双方都禁止将 `questions/` 下的额外文件当作附加资源混入。

学生项目新增对既有 `Exam.Domain` 的引用，仅复用纯逻辑清单验证，不引入数据库或服务器运行时。相应三个锁文件只增加项目依赖，无第三方包版本变更。
