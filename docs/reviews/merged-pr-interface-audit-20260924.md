## 相对最新主分支的修复

### 显示资源只核对文件名，没有核对类型和内容

#52 的读取器会确认附加文件在清单中，但声明了 `assets/raw.tex`、`assets/answer.pdf`、`server-only/image.pdf` 或无效 PNG/JPEG/PDF 时仍能通过。D03 生产端拒绝这些输入，两端约束不一致。Windows 保留文件名如 `CON.pdf`、`COM1.pdf` 也缺少对应拒绝。

新增 `StudentPackageLayout` 作为共同的文件级约定。服务器组包及学生读取均检查显示类型、签名、相对路径、路径长度及保留名。已有服务器专用目录和答案/解析路径拒绝规则继续执行。此类关键词和文件头检查只是补充，不能识别 PDF 正文或图片里是否含答案，不代替服务器逐文件来源核查。

### PDF 的有效文件头掩盖了不完整正文

原读取器只读题目 PDF 的前 5 字节。回归用例保留 `%PDF-`，修改 ZIP 中央目录声明长度，构造正文不足的文件，原代码仍接受。

现在所有题目和附加显示文件都在既有总量限制内读到声明长度，并确认没有额外字节。正文不足、超出声明长度或解压失败均拒绝。扫描使用 64 KiB 临时缓冲区，不将文件解压到磁盘；临时缓冲区用后清零。清单原始字节及失败读取的副本也在结束时清零，但不声称托管字符串或所有历史内存副本都能擦除。

### 校验后的集合仍可被调用方修改

反序列化得到的 `IReadOnlyList` 底层仍是可变集合。调用方可以转为 `IList` 后修改选项或题目列表，导致后续显示和作答使用不同结构。

读取成功后复制并封装科目、题组、题目、选项、显示选项文本和资源清单为只读集合。B03 继续使用既有 `Paper` / `ReadQuestionPdf` 入口，无须另建解析器。

### 解析和冻结边界

完整包扫描移到工作线程，并支持取消。完成解析后再次核对是否结束、撤权、关闭、载荷被替换或参试/版本已变化，再发布清单；已有 SQLite 恢复期间的终止检查继续保留。冻结前额外调用共享完整答卷校验，不在冻结后或服务器端补造缺失记录。
