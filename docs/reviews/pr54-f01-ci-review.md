## F01 发现并修正的问题

**实际宿主状态。** 恢复入口原先只看缓存的 Stopped，外部已经启动、停止中或查询失败时仍可调用恢复协调器。配置修改还把 Faulted 当成已停机。现在要求实际状态明确为 Stopped；恢复后、自检后再次核对，失败或取消保持 Faulted，不返回成功、不自动启动。启动自检期间若宿主被外部启动，也拒绝再发启动命令。

**配置与启动衔接。** 启动前重新读取已持久配置，核对服务器/节点身份及非回退版本，再将该版本交给探针。避免其他配置实例已提交新版本，管理对象仍用旧缓存检查。SCM 适配器只报告服务进程状态，不冒充业务 `/health/ready`。

**取消与无效探针。** 探针返回后再检查取消，防止下游忽略 CancellationToken 后仍触发启动。拒绝 null、未命名和重复检查项目；空集合与阻断项继续拒绝启动/恢复。取消、异常及意外状态不记录成功恢复结果。SCM 等待改用单调计时，避免系统墙钟校准改变超时边界。

**幂等内容绑定。** 备份和恢复缓存原先只匹配 requestId，换操作者、目录或备份标识仍可取得旧结果。现在缓存原请求并逐字段比较；只允许相同请求重放。现有 `PostgresBackupCoordinator` 返回规范化路径，上层接受该合法输出，不用原始路径字符串相等来误拒同一目录。

**配置文件完整性。** 普通 JSON 反序列化会接受重复字段、忽略陌生字段，缺少 HA 布尔字段时默认为 false。现在要求七个字段齐全、唯一，拒绝未知字段和字符串数字，限制为 64 KiB。损坏文件不当作新配置、不覆盖；临时文件发布前再次检查取消。读者允许原子替换时读完旧快照，但仍禁止原位并发写，避免读取操作阻断安全发布。保存和锁等待继续使用部署目录边界，锁等待改用单调计时。
