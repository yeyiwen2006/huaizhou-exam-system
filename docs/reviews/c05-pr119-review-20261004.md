## 基线与范围

按仓库所有者本次明确要求审查、修正并合并。需求基线为 `requirements.md` 的导入、开考后修订、主备源材料同步和恢复检查要求。远端主分支基线 `c3f157a03d4e85ab1b4675832b1b6f28427d1f2f`，原 PR 头 `09892cae91c613a6eb5a6b242c2f53d4175b1456`。本次只使用合成样包及一次性 PostgreSQL，不读取真实试卷，不修改用户原工作区的未跟踪审计报告。

## 发现并修正

1. 归档只有逐文件界限，没有合计解压界限；重复 `materials.json`、重复声明与未声明条目的组合、空条目、非法/保留路径能绕过或异常退出。现在先检查全归档的 256 MiB 解压合计、64 MiB 归档、单文件、数量和深度界限，拒绝链接、大小写别名及文件/目录冲突，文件与清单必须一一对应。
2. 归档自身哈希正确不等于发布材料一致。服务器同时核对归档中的 `manifest.json`、独立答案与发布请求；错误不回显答案或未信任正文。解密、下载和数据库流读取均设内存界限。
3. `SequentialAccess` 读取在流列之后回读前面的列，导致已有归档取回失败。调整列读取顺序，并增加真实数据库回归。
4. GUI/CLI 二进制材料下载此前没有 JSON 接口同等的服务器身份、节点代次、版本与哈希核对。现在共用验证器，拒绝错考试、错版本、过期节点、损坏归档，保留官方业务错误码，不回显代理正文。
5. 原请求重试只固定学生包密文，遗漏源材料密文。现在两份密文均固定；跨进程读取核对原因、声明变更集、归档哈希等不可变字段。已经尝试发布后不能通过重检查悄悄生成另一请求。
6. 共享样式后声明图片搜索路径时可能遗漏直接图片；过深依赖或非法 UTF-8 被静默跳过。现在补充固定点解析并在不能完整核对时拒绝发布。
7. 删除全部归档会被当作旧版本无归档，从而通过恢复检查。`paper.publish` 持久事件增加可选 `materialsSha256` 期待值；归档和事件在同一事务提交。恢复检查核对所有历史版本、实际字节、逐题摘要及解密学生包哈希。无标记的旧事件保持可读；已归档考试不能再经旧 JSON/直接试卷发布接口绕过材料核对。
8. 编辑原因和声明题号会使旧预览失效；已发送请求保持原快照。取回过程中切换考试的旧响应不得写入当前上下文。
