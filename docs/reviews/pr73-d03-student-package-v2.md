# PR #73：学生清单 v2 与加密组包接线审查

2026-09-28，A 按用户授权进行审查、修改、测试与合并。该 PR 在 #70–#72 审查期间新增，原提交 `9aa6dd5fde5376b7aa36ea40b1cf2d6447e8e4d0`，依赖 #72。审查覆盖组包器、共享学生包契约、学生读取器、文件集合、版本语义、加密/解密接线与故障返回。

## 发现与修正

**学生包被过早接受。** 原 `ValidateOptionRegionEntry` 只检查大小和 JSON 根是对象，导致 `{}`、错误考试/版本、重复题目/选项、越界矩形、未知字段和无效 Unicode 等 22 种数据都能通过 `ReadManifest`。现在返回学生清单前即完成严格 JSON 检查、必需构造字段检查、重复属性检查、产物版本/坐标规范/考试/试卷版本核对、题目和选项全集匹配、零起非负页索引、有限正面积矩形范围检查。缺失、重复、额外或非法内容均以 `InvalidDataException` 整包拒绝；读取过程传递取消信号并保持临时元数据清零。PDF 实际页数仍由渲染绑定前的现有检查验证，不把非负页索引当作实际页数验收。

**组包失败边界不完整。** 原组包器在校验前枚举嵌套集合，null 会抛空引用异常；重复选项仅做数量和包含关系判断，可能接受用 A 替换 B 的四项数组；非法几何也未在写出前拒绝。合入 #72 修正后，先调用规范写出器校验原始产物，再核对清单对应关系，并把参数校验失败转为明确的 `OptionRegionInvalid`，不误报为加密或证书问题，也不发布预览/密文文件。

此前交付说明中「共享包层只核对 JSON 形态，逐题语义等到学生端」的限制已由本次审查修正；以当前代码、本记录和回归测试为准。没有为了支持坐标而将普通 JSON 放进显示资源允许集合。

## 兼容、限制与回退

清单 v1 不带坐标，v2 必须带专用根目录坐标文件；坐标文件自身的 artifactVersion 仍为 1。文件不能进入 displayResources，额外包内文件、大小写冲突和路径越界规则未放松。没有更改加密信封、数据库或 HTTP 协议。

生产 C05/CLI 尚未传入 `OptionRegions`，实际生产调用仍默认生成 v1；本 PR 不宣称真实考试已启用原版坐标作答。没有人工 GUI、真实材料、多 DPI 点击、多机故障恢复或 300 人负载验收。本机未配置 PostgreSQL 连接；实库验证依赖最终 CI，不能记作本地通过。#26、#46 保持打开。

回退新组包可不传坐标而继续生成 v1；已发布的 v2 包不得原地改成 v1 或复用旧试卷版本。旧读取器不保证接受 v2，回退时须保留消费者兼容能力或以新版本重新发布。没有删除既有安全断言、停用验证或对主分支强推。
