# E01 本机负载工具与历史基线

当前工具开发、模块自测、隔离数据和报告设施归E01 #30；整项目单机回归归T01 #33，正式多机负载与恢复归T02 #34。原E05 #34现改为T02，已有工具和下文历史实测结果保留其原日期与范围，不代表T01/T02已经执行或通过。开发期间可继续模块性能及工具测试；完整项目测试在全部代码完成后统一开展。

`tests/Load/Exam.LoadTests` 通过正式 HTTP API 和 SignalR 协议访问独立服务进程。它不会直接调用业务服务、替换生产凭据校验或把缺失功能伪造成成功。账号和参试记录由隔离数据准备工具提前建立；准备过程不计入负载结果，因此本工具不宣称已经覆盖激活、登录和进入考试的性能。

## 安全运行

仅允许合成考生、隔离数据库和测试服务。必需显式指定目标原点、合成会话文件、场景、新输出目录及 `--confirm-synthetic`。默认要求有效 HTTPS 证书，不关闭证书验证、不跟随 HTTP 或 WebSocket 重定向。HTTP 只可在显式提供 `--allow-loopback-http` 时访问回环地址，不可用于远程正式考试。

会话 JSON 包含设备凭据和可选考务令牌，应保存在仓库外的私有临时目录，不提交 Git。报告只记录会话序号、耗时、错误类别及计数，不记录凭据、账号、答案、资源正文和服务器错误原文。目标原点会写入报告，分享前仍需检查环境信息。输出目录必须尚不存在，已有结果不会被静默覆盖。

示例命令（先替换为自己准备的隔离合成会话文件）：

```powershell
dotnet run --project tests/Load/Exam.LoadTests -c Release -- --target http://127.0.0.1:5089 --sessions D:/private-load/sessions.json --scenario burst --output D:/private-load/run-001 --confirm-synthetic --allow-loopback-http
```

可选 `--duration-seconds` 默认 60，范围 1–86400；`--timeout-seconds` 默认 30，范围 1–300。下载大包时应显式设置适当超时，例如 120 秒；不能增加验收阈值来掩盖超时。退出码 0 表示本次已运行的本地场景目标满足，1 表示失败、超出阈值或被中断，2 表示参数/配置/文件错误。任何退出码都不代表真实 300 台设备验收通过。

## 会话格式

```json
{
  "synthetic": true,
  "serverId": "isolated-load-server",
  "serverEpoch": 1,
  "questionCount": 120,
  "questionPrefix": "q",
  "optionIds": ["A", "B", "C", "D"],
  "sessions": [
    {
      "examId": "synthetic-exam",
      "candidateId": "synthetic-candidate-001",
      "participationId": "synthetic-participation-001",
      "entryVersion": 1,
      "deviceId": "synthetic-device-001",
      "authorizationVersion": 1,
      "paperVersion": 1,
      "credential": "REPLACE_WITH_PRIVATE_SYNTHETIC_CREDENTIAL",
      "initialAnswerVersion": 0
    }
  ]
}
```

每个会话必须有独立的设备、考生和参试记录。题目 ID 为前缀加从 1 开始的题号，选项来自 `optionIds`；必须与隔离合成题包一致。`questionCount` 至少 120。工具发送完整答案字典，不使用真实试卷常量。真实客户端的空选、多选、不作答等规则由相应功能测试覆盖，本工具当前使用合成单选答案构造容量负载。

初始答案版本须对应数据库已保存版本。重复跑进度场景时应使用新隔离考试，或根据上次报告的 `nextAnswerVersions` 更新会话文件；这个字段是已尝试发送的最高版本，不保证失败请求已经持久化。不得把版本从零重置后覆盖一场已有考试。

## 场景及测量边界

| 场景 | 当前行为与检查 | 明确不包含的内容 |
| --- | --- | --- |
| `burst` | 所有会话同一计划时刻发起真实校时，再发完整进度；合计耗时包括两次请求及答案持久化响应，核对全部答案、版本和授权身份 | 不是只测空校时接口；尚需独立数据库审计确认落库 |
| `steady` | 每会话每 2 秒固定安排一次完整进度，首轮均匀错峰；首次校时立即执行，后续在 60 秒周期错峰；前一进度未结束时将新到达明确记为 `missed-progress-arrival` 失败，不让慢服务器悄悄降低计划负载 | 不包含真实 GUI、本地 SQLite、监测页面、导出及主备故障 |
| `final` | 同时提交完整固定答卷；成功后查询原回执，再以完全相同请求重放，验证回执不变 | 查回执和重放单列统计，不掩盖首次交卷失败；独立数据库审计仍须核对唯一答卷、计分和 outbox |
| `commands` | 独立 WebSocket/SignalR 连接；若有私有 `operatorToken`，全部连接尝试结束后通过正式 API 为每人创建 `ScheduleChanged`；收到后核对授权并回传 `Received`，统计创建、接收、接收加确认耗时 | 不伪报 `Applied`，不模拟学生实际应用 START/END，不代替计划触发到客户端完成业务的 2/3 秒验收 |
| `download` | 同时下载每人声明的资源；校验服务器、代次和试卷版本响应头，流式读到结尾并核对准确字节数 | 不进行文件哈希检验，不解密/渲染、不验证说明齐备，不代表最大真实试题包验收 |
| `mixed` | 建立同批 SignalR 连接后保持到整个场景结束；持续固定频率进度与校时，开始 2 秒后集中下载；持续阶段和下载均结束后集中交卷、查回执及重放，再关闭连接；意外断线及最终连接丢失记失败 | 需要同时提供指令与资源配置；不代替真实 GUI、完整考试、START/END 业务应用或主备验收 |

最终答卷的提交标识由参试记录与进入版本稳定构造；重跑沿用原标识及固定合成答案，答案不依赖清单顺序或本次运行编号。题目及选项配置属于该合成考试的固定定义，提交后不得更改后重新发送。正常负载不自动重试，任何超时和失败都保留在统计中；故障恢复与重试属于后续明确的故障场景。

下载场景每会话额外提供 `resourcePath`（必须以 `/api/v1/resources/` 开头并带合法参试查询参数）及 `expectedResourceBytes`。指令场景可提供顶层私有 `operatorToken` 自动创建合成指令；否则必须给顶层 `expectedCommandEventIds` 并由外部在监听期间发出对应指令，工具等待所有会话收到清单中的事件。若事件按参试记录隔离，应使用自动创建模式，不能把只属于一人的事件列成所有人的预期。

`mixed` 建议至少运行 60 秒，使下载真正与持续答题重叠。持续时间参数只规定答题阶段，连接建立、下载收尾和最后交卷另计，总时长可能更长。指令探针没有业务时限判定不影响进度、下载和交卷各自阈值；任一已评估指标超限、漏发、断连或数据检查失败均会使混合场景失败。它不会继续对已交卷会话主动发进度请求。

## 报告与验收

`samples.jsonl` 保存逐操作样本，`summary.json` 保存运行配置、环境、各类计数、失败数、P50/P95/P99/最大耗时、最大发起延迟和限制。百分位用 nearest-rank，包含失败耗时；固定到达场景从预定时刻计时，另列调度延迟，避免遗漏负载生成器自身排队。所有分位值均按操作类别独立统计。

当前自动判定采用执行指南中适用的阈值：进度 P95≤500ms/P99≤1000ms；集中校时加进度最大≤2000ms；首次交卷 P95≤3000ms/最大≤10000ms；下载最大≤120000ms。指令运输探针等没有对应完整业务验收含义，其 `latencyTargetMet` 为 `null`，不自动宣称 START/END 时限达标。`localScenarioChecksPassed` 表示实际执行的正确性检查及适用时限通过；未评估任何时限的场景，其 `localScenarioTargetsMet` 也为 `null`。任何操作失败或漏发都会使本次场景失败。

每次正式对比还需另附被测提交、数据库版本及配置、服务器/负载机配置、资源大小、主备同步状态、测试时长、考务监测状态，以及只读数据库审计结果。资源监测应区分负载生成器与服务进程，不能把工具保存分位样本的内存算作服务泄漏。

先小规模检查正确性，再逐级增加至 300 个合成会话，最后运行完整考试时长。当前本机回环、单机数据库及合成包结果只能作为本机基线；独立负载机、双 Windows 同步复制、最大实际题包、300 台真实学生机、现场网络、GUI/导出并行及故障接管须分别记录。详见 `agent-implementation-guide.md`“性能与部署验收”。

## 2026-09-23 本机 300 会话基线

本轮使用**全新隔离数据库和全新 300 个合成身份**运行，未连接正式考试数据。负载生成器、服务端和 PostgreSQL 18.6 位于同一台 Windows 机器（14 个逻辑处理器），通过显式允许的 HTTP 回环访问；业务连接池上限 16，未开启同步复制。下载资源是 1 MiB 加密合成字节，不是最大实际编译题包。因此下列结果是本机单机基线，`productionCapacityCertified` 仍为 `false`。

10、50、100、200、300 人的集中“校时 + 完整 120 题进度持久化”均退出 0。300 会话混合场景持续答题 120 秒，并同时保持 300 条 SignalR 连接、创建和确认 300 条合成指令、集中下载、最后集中交卷、查询原回执及重放原交卷请求，整体 `localScenarioChecksPassed=true`、`localScenarioTargetsMet=true`，且没有自动重试。

| 本机混合场景指标 | 结果 |
| --- | ---: |
| 完整进度同步 | 18,001 次，0 失败；P95 25.3 ms，P99 28.6 ms，最大 171.0 ms |
| 校时 | 900 次，0 失败；P95 138.5 ms，最大 155.9 ms |
| 300 条 SignalR 连接 | 0 失败；全部保持约 122.6 秒 |
| 指令收到并确认 | 300 次，0 失败；P95 1,245.0 ms，最大 1,246.5 ms |
| 1 MiB 合成资源集中下载 | 300 次，0 失败；P95 1,680.1 ms，最大 1,762.6 ms |
| 完整 120 题集中交卷 | 300 次，0 失败；P95 684.6 ms，P99 710.9 ms，最大 714.1 ms |
| 交卷后查询原回执 | 300 次，0 失败；P95 633.4 ms |
| 原 `submissionId`/请求重放 | 300 次，0 失败；P95 525.9 ms |

只读数据库审计确认：实际参试 300、已提交 300、最终答卷 300、唯一回执 300、计分任务 300、权威收齐事件 1、待处理收齐检查 0，120 题最终答案逐题核对无异常。收齐事件的数据库处理时间戳比最吏 `received_at` 晚约 189.6 ms；这个值仅作单库诊断，**不是**“最后提交完成到考务 GUI 显示”的 2 秒现场验收。

服务进程最终诊断记录的峰值工作集约 304.8 MB，GC heap 约 125.1 MB，线程池待处理项为 0；critical/API/resource 三类入口累计拒绝均为 0，数据库观测时 16 个客户端连接、1 个 active、0 个锁等待。本次仅持续两分钟，不能据此宣称完整考试时长没有内存增长。

本轮还暴露并修复了一个真实一致性问题：PostgreSQL `timestamptz` 以微秒精度往返，而首次交卷回执曾保留 .NET 的 100 ns 精度，导致“刚返回的回执”与随后从数据库查询的原回执在 `ReceivedAt` 上可能不完全相等。PostgreSQL 存储层现在在生成回执和幂等结果前统一为数据库可往返的微秒精度，并用非整微秒时间值补了回归测试；修正后 300 次回执查询和 300 次重放全部一致。

仍未覆盖：激活/登录性能、真实学生 GUI 与本地 SQLite、最大实际编译题包、完整考试时长、考务监测/导出混跑、双 Windows 同步复制、故障接管、独立负载机、300 台真实学生机及现场网络。正式“支持 300 人”必须继续按 `agent-implementation-guide.md` 的性能与部署验收在目标环境执行。

## 工具自身测试

```powershell
dotnet test tests/Load/Exam.LoadTests.Tests/Exam.LoadTests.Tests.csproj -c Release
```

测试使用受控 HTTP 处理器检查客户端协议和统计，不作为真实服务器压测。真实服务必须单独启动并使用正式端点运行上述场景。不要在同一个 Release 程序正在运行时重建其输出文件；可等运行结束或使用另一个构建配置。
