# C04 学生端在线状态上报（2026-10-05）

补齐需求「实时监测与回收」里**学生端从未上报**的缺口：`POST /api/v1/student/presence/open` 与
`POST /api/v1/student/presence` 此前没有调用方，考务端监测页的「当前页面／题号／题包下载状态／连接状态／
最后通信」在生产里只会显示「未报告／尚未通信」。本次把学生端一侧接通。

## 上报口径

- **一次运行一条连接**：进程启动后首次上报前调用 `presence/open`，保存服务端返回的**代次**；
  之后每次上报都带同一连接标识与代次，序号**严格递增**。
- **立即上报**：登录、选择考试、进入等待、确认参试、开始答题、交卷确认、回收中、交卷反馈、切出/退出。
- **短时间合并**：答题改动与下载状态变化只在**短窗口（默认 500 毫秒，上限 2 秒）**后合并上报一次，
  保证需求「正常联网监测滞后不超过 2 秒」；窗口长度有构造校验，超过 2 秒直接拒绝。
- **60 秒心跳**：挂在既有校时循环上（需求「60 秒校时带完整状态补全」）。内容未变也**占用新序号**，
  因为服务端按序号判定「最后通信时间」，而 135 秒无有效通信就判离线。
- **恢复中**：由指令连接状态推导（`StudentExamRuntime.Reconnecting`），随下一次上报送达。
- **失败处理**：网络失败**保留同一序号与内容**重试（服务端按序号幂等重放，不会重复执行）；
  被业务拒绝（换连接／已退出／同一序号不同内容）时**重新建立连接并补报一次**，且限频 30 秒，
  避免反复冲同一个失败。上报失败只记录 `LastError`，**不影响本地作答**。
- **切出**：关闭前上报「已退出」（限时 3 秒，不拖慢退出）。

## 挂接点

| 事件 | 位置 |
| --- | --- |
| 登录／选择考试／等待／开始答题／交卷反馈 | `src/Exam.Student/MainWindow.xaml.cs` 导航层（五个页面各一处） |
| 确认参试（带上会话与考试） | `Views/WaitingExamPage.xaml.cs` 确认成功后 |
| 下载状态变化 | `Views/WaitingExamPage.xaml.cs` 下载进度回调（合并上报） |
| 题号变化、答案已保存 | `Views/ExamInProgressPage.xaml.cs`（合并上报） |
| 交卷确认／回收中 | `Views/ExamInProgressPage.xaml.cs` 交卷路径 |
| 退出系统 | `Core/StudentExitWorkflow.cs`（关闭前回调）+ `Views/StudentExitDialog.cs` |
| 心跳 | `App.xaml.cs` 校时循环 |
| 上下文（会话／考试／题号／试卷版本／下载状态／恢复中） | `App.xaml.cs` 的 `SnapshotPresence` |

上报器本身在 `src/Exam.Student/Core/StudentPresence.cs`；接口是 `IStudentApi` 上新增的两个方法
（设备凭据路由，`HttpStudentApi` 已有凭据头与 TLS 指纹校验）。

## 与服务端的契约一致性

- 页面取值与下载状态取值都用服务端白名单里的字符串（`StudentPresencePages`／`StudentPresenceDownloads`）；
- **登录页与已退出不携带考生信息**（服务端会拒绝「登录页夹带上一名考生」）；
- `ExamId` 只在有会话时上报（服务端要求两者同时存在）。
