# 系统架构

```text
Exam.Student ──HTTPS / SignalR─┐
Exam.Admin   ──HTTPS───────────┼── Exam.Server ── PostgreSQL
Exam.Cli     ──HTTPS───────────┘        │              │
                                     │         主备同步复制
Exam.Admin / Exam.Cli                 │              │
        └──网络 HTTPS── Exam.Management ──受控服务、资源、备份与恢复
```

## 组件边界

`Exam.Contracts` 定义跨端数据和序列化契约；`Exam.Domain` 承担状态机、输入规则和精确计算；`Exam.Application` 组织业务与事务边界。`Exam.Infrastructure` 提供 PostgreSQL、资源存储、加密和本机持久化适配。GUI、CLI 和 API 不复制另一套业务判断。

学生端和考务端为 WPF 应用，使用 `Exam.Desktop.Shared` 的主题与控件。学生端使用本地 SQLite WAL/FULL 保存答案、标记、位置、冻结快照和待报事件，设备身份及敏感恢复材料由 Windows 当前用户保护。学生机不承担 TeX 编译。

业务服务以数据库事务和唯一约束保存设备编号、名册、参试授权、进度、唯一最终答卷、事件、试卷与规则版本。正式启动不因环境变量而启用内存数据库、无确认应答或未初始化主备状态。

## 数据与长任务

HTTP 入口使用与路由一致的权限分类：学生设备凭据不能访问考务汇总，管理会话不能代替学生设备身份。可靠事件绑定当前授权与版本；重复和乱序投递不能回退考试终态。信任和序列化规则由共享配置固定，时间按需求的时区格式传输。

逐题材料经清单、依赖、真实编译、选项区域、完整计分规则和人工预览检查后发布。学生题包只含允许的显示材料，与坐标、清单按试卷版本原子切换。计分按不可变答卷与当前规则生成，五类报表只在考试结束、实际答卷齐备且当前评分完成时开放。

下载、编译、计分、导出、备份、诊断与关键通知/交卷分别限制资源。持久待发记录不会因为重试次数耗尽而丢弃，取消或失败的半成品不替换完整旧版。

## 主备与独立管理

活动节点本机可靠落盘即可确认业务；备用不可用时自动保持单节点业务并明确显示状态，恢复后补齐数据库、资源和独立确认。DurableFailoverCoordinator 管理持久请求、隔离与代次，方案 A 接管必须先确认旧主已关机或隔离全部业务网络，再验证备机自身持久证据、提升并自动启动。旧主隔离重建，禁止双写和旧数据回灌。

`Exam.Management` 提供经部署配置开放的独立 HTTPS 管理入口，服务控制及审计独立于业务进程。考务 GUI 正常登录后用业务令牌换取管理会话；故障时可从登录页进入独立管理登录。退出或切换账号时清除旧管理权限。CLI保留独立账号登录和业务启停，Windows可用已核验的加密缓存完成停库运维认证，Linux需要数据库可达。管理请求在服务器上执行，考务电脑不直接访问服务器文件或系统服务。GUI合并显示服务器状态，不展示代次，底层身份、版本和代次校验继续执行。

[系统契约](system-contracts.md)说明数据兼容和恢复边界；[验收标准](acceptance-criteria.md)规定真实设备、双机、断电及容量要求。内存实现与回环合成测试宿主仅用于隔离验证，不是可部署业务服务。
