## 已接通的行为

### 在线题包更新与答案保存

生产作答路径由 `PaperUpdateCoordinator` 调用 `StudentExamRuntime.ApplyPaperUpdateAsync`，再进入包管理器和答案会话的联合提交边界。准备、下载、确认参试和解锁仍使用已有正式接口，不新建一套授权协议。

下载期间保留旧包；候选包解密后，先校验清单、考试与版本，再核对题目、选项、编号、题型、弃权约定及科目题组结构。允许修订内容，不允许用在线更新更换作答结构。版本必须前进，保留原答案、私人标记和当前题。

提交顺序为：持久保存受保护的更新意图 → SQLite 事务保存新版本答案和待同步快照 → 发布内存中的题包与运行时版本 → 清零旧明文。SQLite 事务是答案版本的提交点；提交后的控制状态整理不是第二个决定答案成败的提交点。进程重启时用受保护意图和实际答案事务核对已提交版本，本地恢复材料本身不提供本次运行的答题授权。

普通下载、校验和控制文件写入失败不会销毁旧包。答案写入失败会保留旧版并暂停新增作答，恢复写入后通过原更新流程重试；写入结果不明时先回读，无法确认则停止猜测并保留恢复证据。**撤权、考试结束或固定交卷不是“继续旧版答题”的理由**，这些状态优先停止新增作答。

### 指令与结果补报

更新任务以包管理器中的持久指令日志为依据。外场、旧授权、未通过验证或未记录的事件不能进入更新队列，也不能任意上报为成功。准备、确认和更新结果重试保留原请求标识；相同事件已应用后，重复通知重放原 `Applied`，不退回 `Received`。

只有题包、答案和运行时实际版本共同就绪，才能报告 `Applied` 与实际版本。回执核对事件、请求、处理结果、实际版本、失败原因和有效时间；不匹配时保留原请求继续重试。旧版本结果回执暂时丢失不阻塞后续版本安装。协调器空闲与唤醒使用同一个循环，不清空处理中新增的事件。

### 撤权、复核与界面

经过身份、登记和代次验证的设备裁决立即停止旧授权访问；更新解锁接口明确返回 `AuthorizationRevoked` 时也进入停用路径。已保存的本地答案不会删除，界面只说明服务器保存了此前确认同步的进度，不声称所有本地内容都已上传。

安装记录在受保护的包控制记录中持久保存；复核确认存入 SQLite 的 `paper_update_review`。重启后仍能恢复待复核版本。考生阅读修订内容后点击按钮，确认绑定其看到的确切版本；旧版本操作不能确认后来安装的新版本，同一版本重复确认保留首次确认时间。

等待页保留设备冲突提示和重试，卸载后不再发起新的页面操作。正常退出系统会先释放本窗口的快捷键限制与置顶状态。

### 本地库与快捷键边界

SQLite v1 → v2 只增加复核表，不删除或重建原答案。迁移前核对数据库身份、完整性和既有结构；数据库事务已完成但身份侧文件未完成时，只有验证匹配后才补完身份文件。身份错误的原库不会先被修改后再遭拒绝。

快捷键判定不再把低级键盘事件的 `0x02` 标志当成 Ctrl；Ctrl 状态独立传入。安装失败明确提示，不能静默宣称防护正常。系统安全界面、强制结束进程不在普通用户态快捷键防护的保证范围。本轮没有进行真实键盘或现场普通账户验收。

## 未完成的接线

**失焦事件尚未形成持久留痕链路。** `FocusTracker` 仅统计当前页面会话，正在失焦的区间计入次数，时长使用单调时钟。焦点变化会立即核对原答案快照，但不改变答案版本或请求身份。原 PR 新增而服务端不消费的 `SyncProgressRequest` 字段已撤回，避免“新请求 ID + 相同答案版本”触发版本冲突并封锁作答。当前界面明确显示无服务器留痕回执；本地持久事件、离线补报、发生和接收时间及考务展示仍需独立交付。

复核确认目前只在本地保存，尚无服务端确认上报和考务端区分“已更新但未复核”的完整链路。修订题号清单也尚未接入；不能把提示复核整个试卷记作已完成逐题变更提示。

本轮自动测试不代替人工 GUI、多 DPI、真实材料、真实主备、断电恢复、300 人或完整考试时长验收。任务 #14 保持打开，不能依据本 PR 宣称 B06 全部完成或跳过 T01/T02。
