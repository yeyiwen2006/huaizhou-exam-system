## 改动与原因

| 问题 | 原因与修复 |
| --- | --- |
| 触控板进入其他桌面 | 键盘钩子并不控制 Windows 的任务视图手势。学生端从启动起进入不运行 Explorer 的独立 Win32 桌面，守护进程在界面退出后恢复原桌面；不修改系统触控板设置。登录页仍能移动、缩放、关闭，登录后全屏。 |
| 新设备被信任信息拦住、无法下载 | 公网入口证书与原节点证书曾被混用；现在独立保存入口和原节点身份，重复登录保留已批准映射。新设备完成身份登录即登记换机冲突，不依赖旧设备在线或新设备先下载试卷。获批后沿用同一参试记录和新授权，旧授权失效；题包入口跟随可信活动节点，HTTP 5xx 可走已有受限重试。 |
| 单科均分漏人 | 每科及其小题使用该科非零样本；总分保持全科非零样本；班级使用对应样本。计算与独立结构、一致性校验一起更新，保留精确有理数及空样本语义。 |
| 主备行跳动或短暂双主 | 节点按固定标识排序，保留行对象、选择和滚动。角色只来自一份已核实集群快照，本机数据库物理角色只作健康信息。接管和重建期间保留原角色，完成后先同时写入两行再发送更新通知。 |
| 状态轮询反复出现暂停、未核实 | 忽略子控件冒泡的 Loaded/Unloaded；手动刷新和自动轮询共用一次有界查询，取消一个等待不取消其他读者。短暂网络失败保留原证明至原到期时刻，统一有效期 30 秒，不延长旧证明、不把失败结果当成功。 |
| 重建失败、只能切换一轮 | 读取历史代次确认目录时正确找到对应 `epochs` 目录。双侧证明按固定持久边界比较，允许同身份、同资源摘要的更晚确认覆盖；不追逐恰好相等的最新确认头或瞬时零延迟。重建启动只核对固定数据库状态和可失效的资源摘要缓存，等待上限 5 分钟；完成后的协调核对有界重试，不重复提升数据库。旧槽清理暂不可用时保留并记录，不把已验证重建改为失败。 |
| 不作答按钮 | 同页同一横行的 A–D 以两端圆心中点对齐按钮中心；上下分行和跨页仍与 A 圆圈左端对齐。 |
| 接管后仍连旧主 | 考务端登录后读取经认证的节点拓扑，受保护保存路由；接管核实完成主动切换，普通业务失败也可触发同一受限重连。先无凭据核对可信候选的逻辑身份、节点及代次，再验证原会话，保留页面和原写请求编号。学生端沿用原设备与答卷自动重连。重启预填最后活动地址，原启动入口指定旧地址时仍可发现已登记的新主。 |

健康活动节点单独存在时登录不等待另一节点上线。只读备库必须先按原隔离与确认流程接管；客户端不能因连接失败自行提升数据库。

## 最小必要核验

固定数据库系统身份、时间线、服务代次、已确认 WAL 位置、资源摘要、证书和解锁材料仍须一致。删去的是“持续写入时瞬时延迟必须为零”和“两个不断前进的确认头必须完全相同”这类移动目标。重建复制和安装仍保留完整性检查，资源变化、目录替换或通知异常会使缓存失效。

学生端时钟读保持有界等待；响应较慢时至多探测已登记的另一节点，复用重连锁及失败退避。慢但健康的当前节点可继续返回，只有可信、更高代次的活动节点能触发换路。考务启动探测到可信活动节点后不再等待旧节点超时。没有增加考试答卷全量扫描或跨节点逐题核对。

基线已有负重放差值归零显示、预期备库只读检查、受限探针连接池及对端材料缓存，本轮继续保留。此前外部报告的“新 TCP 超时必然由数据库连接耗尽导致”证据不足：应分别核对主机本地连接、实际连接构成、监听端口与网络路径，不能仅据截图扩大连接上限、终止连接或清理复制槽。本次未对现场执行这些操作。

## 追加修复：隔离节点显示与长期待核对请求

本轮在提交前重新获取远端，并以最新 main `80efb34` 为基线整合。保留该版本的管理连接自动跟随、旧节点向可信对端核验考务会话、首次显示完整角色快照和重建准备失败收尾逻辑。

### 原因与处理

| 现象 | 已核实的代码路径与修复 |
| --- | --- |
| 新主可达，角色和保护仍待核实 | 接管后的新主仍等待已隔离旧节点的业务材料探测。新主现在依据实际数据库角色、受保护的部署选择、同代次同版本状态及原接管审计，独立确认当前权威。仍明确标为单节点保护，旧节点的连接和材料保持各自真实状态；不把超时当作隔离证据。 |
| 原请求已完成，页面仍冻结角色 | 原请求核对只有 3 秒，且只自动查询当前连接上的请求。现在认证与原请求查询共用 25 秒预算，自动核对所有已保存节点的原请求，手动和自动查询共享同一任务。匹配请求号、账号、内容摘要与节点的终态到达后，发布已有的新鲜完整角色快照。 |
| 无法点击旧节点重建 | 当前节点无证明时仍允许对已配置目标先认证和只读查询；真正变更仍要求目标最新证据及确认。保留新主连接。自动会话核验未获授权时，显式操作可进入同页独立认证；网络故障不会被描述为密码错误。后台失败交换按节点退避 30 秒。 |
| 高并发时重建一直“需要核对” | 初次执行已有独立工作期限，但恢复核对原先受 HTTP 查询取消控制。现在同一原请求的恢复由服务端继续执行，沿用 90 分钟工作上限和持久日志互斥；并发读只返回当前阶段，不重复安装。界面等待取消不取消服务器工作，页面停留期间每轮完成后间隔 10 秒继续查询。 |
| 反复查询让已安装备库不断重启 | 以原请求的暂存、已安装和隔离目录身份识别已经完成的目录交换。重入时保留正在回放的 PostgreSQL，仅做固定身份、状态和已缓存资源清单核对；没有增加答卷或试题全量扫描。 |

查询可返回临时 `failoverWorkInProgress` 标记，界面显示“正在处理原请求”。该标记不写入持久日志，默认省略，已有日志保持兼容。缺失、绑定不符、证据不足的请求不会因等待时间长而被删除或伪装为完成。

重建准备尚未安装且本机证据证明安全失败时，沿用最新基线的正式失败结案；保留旧目录、原请求和审计，复制槽清理不阻塞结案。进入安装阶段的请求按原计划续办。只有完成或确认安全失败后，才能继续发起下一次重建。
