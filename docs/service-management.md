# 服务器管理

考务端提供独立管理登录、退出、状态、启停、自检、版本化配置、限定日志、备份、隔离恢复和原请求查询。主备管理提供状态、手动接管、单机应急、旧节点重建和恢复同步保护。

业务登录页和业务顶栏均可进入管理页，管理会话不授予业务页面权限。业务断连不会切走管理页；返回保留业务页面及尚未确认的注册结果。保护警示显示在主窗口，返回业务登录、退出管理会话、断线和客户端重启均不会自动解除已知降级警示。

GUI 源文件链接共享 `LocalManagementClient.cs`，没有 SQL、SCM 或备份执行入口。正式持久协调与部署见 [管理契约](high-availability-management.md)。

## 操作流程

1. 在考务端登录页或业务顶栏进入“服务器管理”，考务端可以和服务器位于不同设备。部署连接已配置时，只需填写已启用的考务账号和密码；地址与内部标识放在默认折叠的“连接设置（部署人员）”中。缺少或无法读取配置时，页面提示联系部署人员，并提供“导入连接配置”。连接使用 HTTPS，证书须受考务电脑信任，域名或 IP 须与证书匹配；不接受 HTTP、重定向或证书绕过。
2. 查询状态。进程、业务就绪、代次、主备模式、复制、材料及证书分别显示。未知代次不补成 0；空检查不报告通过；配置勾选不能证明同步保护已生效。
3. 启停、自检、配置、备份和恢复均需确认。配置携带读取版本，冲突保留表单；重新载入、比较并确认后才能形成新请求。后端继续执行停机、权限和路径检查。
4. 备份须证明数据库、受保护配置与版本资源完整。恢复分开显示隔离暂存、核对与业务就绪；缺最新确认继续阻断，只有正式支持的恢复阶段允许显式续办原请求。
5. 主备变更先查询最新状态，填写已配置目标及原因，再确认影响。接管时须连接存活备用节点的管理宿主，必须明确确认旧主断电或业务网络隔离；不可达和心跳超时不足以接管。
6. 单机应急先停止业务再切换受保护部署，完成后自检并启动业务，持续显示保护降低。重建请求须发往旧节点自身的管理宿主，确认替换旧数据并保留隔离副本，禁止回灌旧库。完成重建后，在活动主节点核对备用节点并恢复同步保护；应急后已恢复并追平的原备用也可直接核对恢复保护，无须强制破坏性重建。
7. 接管提升后目标节点业务保持停止，按自检及 “启动服务”流程启动，使业务宿主读取新代次和确认目录。重建启动非活动节点确认监听，业务写入仍由原门禁拒绝。
8. 响应丢失、取消等待或重启后查询原请求。未找到不证明未执行；仅在明确确认后按原号、原账号、原节点和原内容重试。主备查询不会自动再次提升或再次破坏性重建。

管理页面中的服务配置不包含秘密；口令提交后清空，令牌只在独立连接内存中，退出或释放清除。退出网络失败明确显示服务端撤销未确认。

## 首次部署连接配置

考务端优先读取当前 Windows 用户保存的管理连接；没有用户记录时，自动读取 `Exam.Admin.exe` 同目录的 `management-connection.json`。连接文件仅包含 `address`、`serverId`、`nodeId` 三个字段，不含账号、密码、数据库连接串或证书私钥。界面导入成功后立即保存到当前用户的管理记录目录，下次打开可直接登录。

部署人员在管理服务所在机器上，根据实际生效的管理配置生成连接文件。以下命令中的路径须替换为本机部署位置；若管理配置由多个来源合并，输入文件中的 `Management.HttpsPort`、`Management.ServerId` 和 `Management.NodeId` 须与服务最终生效值一致。

```powershell
pwsh -File deploy/management/Export-AdminConnection.ps1 -ManagementConfigurationPath "C:\Exam\Exam.Management\appsettings.json" -AdminDirectory "C:\Exam\AdminConnection" -HostName "manage.exam.example.invalid"
```

导出时用 `-HostName` 指定考务电脑能够访问的管理域名或 IP。工具仅把地址、服务器标识和节点标识写入连接文件，不复制完整部署配置。将生成的 `management-connection.json` 交给考务人员，通过“导入连接配置”导入，或放在考务端程序旁。业务地址与管理地址分别配置，管理服务使用独立监听端口；端口随连接文件分发，考务人员登录时无须填写。

已有用户记录优先于随安装提供的配置；更换管理端口或节点时，重新导入连接文件，或在折叠区由部署人员修改并保存。无效导入不会替换原连接。生成的 `management-connection.json` 已从 Git 和两个源码目录的同步中排除。

在服务器上显式设置 `Management:BindAddress` 为可接收远程连接的网卡 IP，或 `0.0.0.0`，并为管理端口配置防火墙访问范围。未设置时仍只监听本机。管理页面中的数据目录、备份目录和工具目录均属于目标服务器，例如 Windows 的 `D:\Exam\data` 或 Linux 的 `/srv/exam/data`。正式部署流程见[服务器部署](../deploy/server/README.md)。

Windows 管理服务会保留经数据库核对的账号加密缓存，数据库暂不可用时仍可用已缓存账号登录。Linux 不保存这份 Windows 专用离线缓存，登录需要数据库可达；业务服务停止不影响独立 PostgreSQL 的运行。Linux 支持基础状态、自检、配置、启停、日志和备份，隔离恢复及主备变更继续使用 Windows 部署。

## 持久请求与警示

变更发送前，在当前 Windows 用户 DPAPI 下保存原请求、目标、已认证操作者和内容摘要。一个节点只保留一个未解决请求；独占锁和原子移动防止其他考务实例覆盖。损坏、写入失败或链接路径阻止发送，不删除待核对记录。记录不包含口令、会话、响应体、试题或原始日志。

短读取和最长 65 分钟变更分别设定期限。离开页面停止读取与等待，保留原请求；旧连接响应不能改变当前页面。原请求轮询最多 10 次，每次间隔 2 秒，只查询、不重发、不重叠。确认终态前核对请求、目标、操作者、类型、摘要和阶段证据。

主备状态超过 10 秒或缺证据时显示未核实，禁止新的主备变更。解除警示须有当前状态、实际复制、材料、证书和双侧最新持久确认，零延迟不能替代。每个目标的降级警示另用 DPAPI 保存；记录损坏保留警示。日志只展示固定元数据，每类最多 50 条，无任意文件或原始消息入口。

已显示的保护证据也会按时失效，不依赖下一次网络响应。重新登录或重启后，低于已保存代次、版本或同版本核实时间的响应不能解除应急警示。检查名称、日志来源/级别和隔离确认采用中文，时间按 UTC+8 显示。

## 验证与运行边界

```powershell
dotnet restore Huaizhou.ExamSystem.sln --locked-mode
dotnet build Huaizhou.ExamSystem.sln --no-restore --configuration Release
python eng/testing/run_checks.py --profile core --profile wpf --output .artifacts/management/final
python eng/testing/run_checks.py --profile postgres --profile postgres-physical --postgres-bin <tool-directory> --native-physical --output .artifacts/management/final-postgres
```

管理接口、持久请求及数据库恢复分别使用对应分类测试。WPF 离屏渲染不能代替真实显示器 DPI、SCM 服务账户、现场证书或实际危险操作确认；原生 PostgreSQL 演练也不能代替两台独立主机的网络与断电验收。

## 恢复与回退

回退界面前保留加密原请求、保护警示和服务端日志。已提升或重建后不能靠代码回退撤销角色；禁止自动切回或合并旧库。根据实际持久代次与隔离证据选择恢复方式。
