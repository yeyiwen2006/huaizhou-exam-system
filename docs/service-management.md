# 服务器管理

考务登录后可直接进入“服务器管理”，不再输入第二次账号和密码。页面提供主机与备机分别显示的服务器状态、独立的自动备份与磁盘区域、主备运行与故障接管和操作与事件日志。两台管理服务各自检查本机，考务端分别刷新；一台离线或超时只影响自己的节点行。主备运行、日志和服务器状态使用相同标题样式，保持展开；单节点业务自动可用。

管理会话由当前业务令牌安全换取，服务端核对已登录账号和权限。退出考务、切换账号或业务会话失效时清除旧管理权限。返回业务页面不会丢失尚未确认的操作记录；主备、自动备份与磁盘提示仅在服务器管理页显示，解除告警仍须有对应证据。

接管后，管理页面沿用同一考务身份跟随已核实的活动节点。隔离旧节点向部署中已配置并固定证书身份的对端读取一次当前考务身份，最多等待150秒，再签发独立的本机管理会话，无需再次输入密码。后续状态、日志和原请求查询只验证管理令牌，不再为每次刷新查询账号数据库，也不每分钟向新主重复认证。管理会话最长24小时，退出登录或管理服务重启后失效。

角色优先使用考务登录已确认的活动节点，以及活动节点独立返回的部署状态，不等待跨节点保护检查。隔离旧节点仍可有可写的旧数据库，界面显示“旧库（待重建）”，不将其列为当前主库。连接失败保留上次观察并标注，主机、备机状态卡按活动角色对应节点。管理连接及读取上限为150秒，主备观察有效期为3分钟；切换页面不延长已有观察的有效期。

考务端可部署在独立电脑上。顶部保护提示描述整个服务器集群，明确显示“当前主机：节点标识”，不随本次查询节点切换成“当前为备用节点”。业务数据保存在主服务器上，考务电脑本身没有主备角色。

同一集群切换管理查询节点，或离开再返回管理页面时，保留尚未到期的保护观察，避免先清空再恢复造成黄色告警闪动。观察仍按原时间到期，不因切换或返回页面延长有效期。

接管和重建确认提交后，顶部直接显示“接管中／重建中”，后台确认终态后自动显示“接管成功／接管失败／重建成功／重建失败”。普通刷新或自动跟随管理节点不覆盖结果，不再提示考务人员手动查询请求。跨机数据库建立连接的期限为60至90秒，远程管理数据库查询至少允许30秒，本机连接仍使用原有短期限；已隔离旧库不会在连接新主失败后重新充当当前权威。

数据库基础备份允许120分钟，整个接管或重建允许150分钟，客户端操作等待允许155分钟。管理页外层等待与管理读取使用同一150秒期限，避免界面提前取消仍在进行的读取。已受理操作使用独立于页面和HTTP连接的执行期限；升级前已开始的操作继续沿用启动时的计时器，修改源码或配置不会延长它。

重建复制会话与新备库的复制空闲超时为10分钟。数据库复制工具失败时，在本次暂存目录保存脱敏后的 `basebackup-failure.json`，请求结案保留原失败原因。已安全结束的失败或取消请求保留旧数据和暂存文件；新重建开始前清理本系统已确认废弃且未使用的复制槽，避免多次取消耗尽复制槽。

接管和重建进行时可点击“取消接管／取消重建”。取消意图先持久保存，再通知执行进程停止；正在复制的进程会退出，完成后按钮禁用。已开始的提升或目录交换先结束必要的原子步骤，保留生效的角色和数据，不自动切回旧主。服务器确认取消后显示“接管已取消／重建已取消”，解除本次请求占用，允许重新发起仍适用的操作。切换页面、业务断线和取消操作使用不同的生命周期，切换页面不会发送取消请求。

考务端只保留统一登录页的一组账号、密码和一个“登录”按钮。先尝试考务业务；业务连接不可用时，使用本次输入的同一组账号密码登录已配置的独立管理节点，并显示“考务服务暂不可用，已进入服务器管理”。业务返回账号或权限错误时直接提示登录失败。登录结束立即清空密码输入，不在磁盘或后续重连任务中保存明文密码。

业务正常时自动换取独立管理会话；管理节点之间通过已确认的管理身份换取各自会话，不再显示逐节点密码表单。业务恢复时，管理通道仅向当前活动数据库为已认证账号签发考务会话，业务端确认账号、节点和代次后进入考务页面。现有节点连接、原请求和后台任务均保留；单个节点的认证或连接失败只影响该节点。

GUI 源文件链接共享 `LocalManagementClient.cs`，没有 SQL、SCM 或备份执行入口。正式持久协调与部署见 [管理契约](high-availability-management.md)。

## 操作流程

1. 在统一登录页登录，业务可用时进入考务，不可用时自动进入服务器管理。考务端可以和服务器位于不同设备。部署人员预先配置管理连接，HTTPS 证书须受考务电脑信任，域名或 IP 须与证书匹配。界面不提供切换登录方式或逐节点登录表单。
2. “当前管理服务器”同时显示已配置主备节点及地址，“服务器状态”分主机和备机展示，不展示代次。刷新中或读取失败时保留节点身份及最近观测，标明未知、失联或过期，不清空表格，也不将旧观测显示为当前正常。
3. 右上角“刷新”统一读取服务器、主备、自动备份与磁盘以及日志。“自动备份与磁盘”在“服务器状态”下方独立成框；服务器和备份的告警只在本页展示。状态检测继续检查当前配置和实际运行条件。
4. 页面取消“服务器配置”“备份与恢复”框及业务启停、原内容重试和恢复续行按钮。配置与恢复由正式管理 API 和 CLI 处理，旧备份缺少后续已确认数据时仍阻止开放业务；失败、核对不通过或尚未就绪时不显示完成。
5. 点击主备节点表中的目标行，自动填写“所选服务器节点”；备注选填，审计记录操作者、目标和结果。接管仍须真实确认旧主断电或全部业务网络隔离，并核对备用副本。业务不可用时由统一登录自动进入管理，考务人员不选择服务类型。
6. 接管自动读取新的部署选择、启动业务并检查就绪。接管成功后旧主角色显示“隔离”，旧主的较早本机观察不能覆盖新角色。选中隔离节点，可点击接管按钮右侧的“重建隔离的服务器并作为备机”；确认后从当前主机重建，保留旧数据隔离副本。恢复同步保护保留管理 API 和 CLI。正常备机重新追平后自动核实双节点保护。
7. 页面不显示请求编号输入、手工查询按钮和顶部请求处理状态。响应丢失、取消等待或重启后，后台继续使用原请求编号核对，不重新执行操作；人工查询使用正式管理 API 或 CLI。原请求记录继续保留，防止重复提交。

管理页面中的服务配置不包含秘密，也不保存考务密码。换取的管理令牌只保留在当前连接内存中，退出、账号切换或释放连接时清除，界面无法继续使用旧管理身份。

## 首次部署连接配置

考务端优先读取当前 Windows 用户保存的管理连接；没有用户记录时，自动读取 `Exam.Admin.exe` 同目录的 `management-connection.json`。单节点连接文件包含 `address`、`serverId`、`nodeId`，双节点部署还包含 `peerAddress`、`peerNodeId`。文件不含账号、密码、数据库连接串或证书私钥。管理连接由部署文件提供，界面不再提供导入和切换入口；已有受保护用户记录继续按原配置规则读取。

部署人员在管理服务所在机器上，根据实际生效的管理配置生成连接文件。以下命令中的路径须替换为本机部署位置；若管理配置由多个来源合并，输入文件中的 `Management.HttpsPort`、`Management.ServerId` 和 `Management.NodeId` 须与服务最终生效值一致。

```powershell
pwsh -File deploy/management/Export-AdminConnection.ps1 -ManagementConfigurationPath "C:\Exam\Exam.Management\appsettings.json" -AdminDirectory "C:\Exam\AdminConnection" -HostName "manage.exam.example.invalid"
```

导出时用 `-HostName` 指定考务电脑能够访问的管理域名或 IP。工具仅把地址、服务器标识和节点标识写入连接文件，不复制完整部署配置。将生成的 `management-connection.json` 放在考务端程序旁，由部署人员核对已有用户管理记录与部署配置一致。业务地址与管理地址分别配置，管理服务使用独立监听端口；端口随连接文件分发，考务人员登录时无须填写。

已有用户记录优先于随安装提供的配置；更换管理端口或节点时，由部署人员更新实际读取的连接文件并重新打开考务端。配置仍须通过格式、身份和 HTTPS 校验。生成的 `management-connection.json` 已从 Git 和两个源码目录的同步中排除。

在服务器上显式设置 `Management:BindAddress` 为可接收远程连接的网卡 IP，或 `0.0.0.0`，并为管理端口配置防火墙访问范围。未设置时仍只监听本机。管理页面中的数据目录、备份目录和工具目录均属于目标服务器，例如 Windows 的 `D:\Exam\data` 或 Linux 的 `/srv/exam/data`。正式部署流程见[服务器部署](../deploy/server/README.md)。

正式管理 API 和 CLI 保留独立账号登录、业务启停、原请求重放及恢复续行。Windows 管理服务保留经数据库核对的账号加密缓存，数据库暂不可用时可用于独立管理登录。Linux 不保存离线缓存，管理认证需要数据库可达。Linux 支持状态、状态检测、配置、启停、日志和备份，隔离恢复及主备变更继续使用 Windows 部署。正常 GUI 复用考务会话；业务不可用时提供独立管理登录以完成接管。独立登录仍由管理服务验证原账号和权限。

## 持久请求与警示

变更发送前，在当前 Windows 用户 DPAPI 下保存原请求、目标、已认证操作者和内容摘要。一个节点只保留一个未解决请求；独占锁和原子移动防止其他考务实例覆盖。损坏、写入失败或链接路径阻止发送，不删除待核对记录。记录不包含口令、会话、响应体、试题或原始日志。

短读取和最长 65 分钟变更分别设定期限。离开页面停止读取与等待，保留原请求；旧连接响应不能改变当前页面。原请求轮询最多 10 次，每次间隔 2 秒，只查询、不重发、不重叠。确认终态前核对请求、目标、操作者、类型、摘要和阶段证据。

主备保护观察超过60秒时标记过期，已有角色和上次状态继续显示。接管要求当前备机的有效状态；重建可先使用新主返回的代次和版本，避免要求隔离旧库先拥有新状态。服务端在执行前核对当前权威、目标、代次和版本，禁止重建活动主机。原请求在后台自动查询，终态到达后解除占用，不阻塞其他节点的状态刷新。双份数据保护仍依据实际复制及双侧持久确认显示。“操作与事件日志”每类最多50条，只展示固定元数据。

已显示的保护证据也会按时失效，不依赖下一次网络响应。重新登录或重启后，低于已保存代次、版本或同版本核实时间的响应不能解除单份数据警示。检查名称、日志来源/级别和隔离确认采用中文，时间按 UTC+8 显示。

## 验证与运行边界

```powershell
dotnet restore Huaizhou.ExamSystem.sln --locked-mode
dotnet build Huaizhou.ExamSystem.sln --no-restore --configuration Release
python eng/testing/run_checks.py --profile core --profile wpf --output .artifacts/management/final
python eng/testing/run_checks.py --profile postgres --profile postgres-physical --postgres-bin <tool-directory> --native-physical --output .artifacts/management/final-postgres
```

管理接口、持久请求及数据库恢复分别使用对应分类测试。当前尚未操作真实服务器；真实显示器 DPI、服务账户、现场证书、两台独立主机网络和断电恢复仍需在目标环境验收。

## 恢复与回退

回退界面前保留加密原请求、保护警示和服务端日志。已提升或重建后不能靠代码回退撤销角色；禁止自动切回或合并旧库。根据实际持久代次与隔离证据选择恢复方式。

本机双节点联调可使用同一主机地址上的不同端口。可信节点按 HTTPS 地址（含端口）和节点身份区分，不再要求两个节点必须使用不同主机名。
