# B02 等待与解锁实施状态

本实现以 requirements.md 为行为依据，接入当前 A 组 PostgreSQL API 和 SignalR。生产入口没有 Mock、演示 START 或第二套合成题包格式。

## 已实现的流程

选择考试后先显示等待页，再获取准备记录、完整密文题包及同版本说明。下载和说明任一失败，均不能确认实际参试；资料齐备后提交确认，服务器在事务中再次核对时间、资源、设备与当前名册。只有确认后才有实际参试登记。

- HTTPS 下载绑定 preparationId、sessionId 和设备凭据，凭据只放请求头；拒绝跨源地址、重定向、错误响应类型及版本，设置下载/读取超时和长度上限。
- 文件按逻辑服务器、考生、考试与题包版本隔离。临时文件完整写入并刷新后才替换最终密文；失败不发布半包，损坏包保留并允许重新下载。
- 公开说明使用持久化 InstructionsDocument（Version、Lines），与准备记录的 InstructionsVersion 一致；页面实际呈现返回内容，中文黑体、数字 Times New Roman。
- 进入准备、参试确认、退出和指令确认的未决请求均保存原请求标识。响应丢失、程序重启和重新登录后先查明原操作结果，不生成重复参试，不把未知退出视作成功。
- 等待页退出使用当前服务器 Version，只在收到 NotParticipating 回执后离开。已经开考、已结束或授权变更由服务器拒绝，页面不删除实际名单。
- 已开考的合法迟到进入从确认结果立即取得当前状态；实时连接建立和重连后 CatchUp，连接期间每 30 秒补查。后台即时推送与补查共用持久事件和确认，不依赖只收到一次 START。
- 事件核对服务器身份和代次、考试、参试标识、登记版本、设备及授权版本。START 只有实际解密成功才确认 Applied；END 和明确授权撤销清除明文并阻止迟到 START 重开。
- 真实 SignalR 使用 WSS，不在查询参数传设备密钥，不绕过 TLS。明确授权拒绝与普通网络故障分开处理；页面切换后仍保留当前考试指令连接。
- 接收回调不等待慢速解锁完成，END 和授权撤销可及时触发停用。普通在途指令上限 16 个、END 独立保留容量，同事件重复投递合并；超限不确认，由持久补发重试。连接关闭等待已接收任务，补查同批指令先处理 END。
- 程序重启不凭本地缓存单独解锁。重新验证当前服务端授权后，使用原密文和当前合法解锁材料恢复；已确认过 START 也可以恢复，不依赖服务端重发已确认事件。
- 本地控制恢复记录及解锁材料使用当前 Windows 用户 DPAPI、原子替换和受保护备份。题目明文仅存在于通过完整认证后的内存，不落盘；答案与私人标记的 SQLite WAL/FULL 持久化仍由 B04 实现。

## A 组配套接口

- GET /api/v1/student/exams?sessionId=...
- PUT /api/v1/student/exams/{examId}/metadata：考务身份发布公开配置与上游生成的说明，带 requestId、expectedVersion。说明保留历史版本；初始配置接口在考试开始/结束后拒绝修改，避免绕过正式版本发布链。
- GET /api/v1/student/instructions?preparationId=...&sessionId=...
- GET /api/v1/resources/{resourceId}?preparationId=...&sessionId=...
- POST /api/v1/resources/unlock：请求包含参试、登记、授权、题包、解锁引用和服务器代次。

解锁服务在数据库事务内重新核对活动节点、设备激活、实际开考、截止时间、当前唯一获准登记及题包信封；撤销后重试不能取得旧密钥。发放后的密钥不会保存到幂等响应表，HTTPS 响应标记 no-store，服务端响应完成后清零密钥。

服务器与学生端共享 HEXAMPKG v2 解密器，校验 AES-GCM 分块、包标识、版本及认证结束记录。错密钥、错版本、截断、调换和尾随内容均不能变成成功解锁。

已有实际参试者在首次进入截止后仍可恢复连接和资料；确认结果用 Lifecycle=Ended 表明只能恢复后续补传，不提供新的解锁引用。已交卷、已退出且过期的记录不能借此重新入场。

## 运行配置与依赖

使用仓库锁定的 .NET 10 SDK、PostgreSQL 18 和依赖锁文件。学生机须信任部署的 HTTPS 服务器证书；程序不会接受任意自签证书或跳过验证。

服务器通过受保护配置设置 PackageSecurity:CertificateThumbprint。相应节点私钥必须位于运行服务账户可访问的 Windows LocalMachine/My 证书库，且与发布信封中的该节点公钥相匹配。缺少配置或私钥时解锁明确失败，不回退到演示密钥。活动节点身份须已初始化；开发模式允许空主备状态也不能绕过发钥检查。

真实题包来自 D 的正式组包发布流程。本次自动化测试使用独立合成输入和临时节点证书，未导入或上传真实试卷、个人信息或部署私钥。

## 验证与边界

测试包括真实 v2 密文、下载中断/超长/说明错版、身份路径隔离、确认/退出/ACK 掉回执后的原请求恢复、已签收 START 后重启恢复、终态和授权拒绝，以及真实 Hub 的推送、补发、签收、慢解锁并发终态、有界接收及授权失效。服务端另有 PostgreSQL 实库事务与截止竞态回归。本机 197 项测试通过，环境、分类及已观察到的测试宿主收尾日志见 [B01/B02 复核记录](b01-b02-review-verification.md)。

本 PR 完成 B02 等待、参试确认及真实解锁模块，不等于整个考试系统可正式使用。B03 PDF 与选项、B04 答案落盘、B05 补传与最终交卷、B06 更新应用及现场限制、B08 主备地址切换仍由各自任务负责。当前收到试卷/时间更新只记录 Received 并提示未完成更新，不谎报 Applied；答题占位页禁用作答和提交，不产生假回执。

本轮未做真实学生机视觉验收、300 台现场演练或两台 Windows 主机切换，不将本机测试写成这些场景已通过。
