# ADR 0002 本机管理入口、身份验证与接口边界

2026-09-26，A 确认 F01 的实施边界。关联 [F01 #7](https://github.com/yeyiwen2006/huaizhou-exam-system/issues/7) 及 [F 的接口确认请求](https://github.com/yeyiwen2006/huaizhou-exam-system/issues/7#issuecomment-5835054583)。F 负责实现，A 审查具体代码、契约及验证结果。本记录确定后续接线规则，不代表独立管理宿主已经交付。

## 需要解决的问题

[需求](../../requirements.md)要求业务停止后仍能从考务端服务管理页或 CLI 启动服务，备机管理入口也不能依赖旧主在线。现有 [ExamApiAccessMiddleware](../../src/Exam.Server/Runtime/ExamApiAccessMiddleware.cs)先执行依赖 PostgreSQL 的活动节点检查，再验证考务令牌，不能整条复用于停机管理。

现有令牌与 OperatorId 由 [PostgresRuntimeRegistration](../../src/Exam.Server/Runtime/PostgresRuntimeRegistration.cs)读取受保护配置。身份校验本身可以独立于数据库运行，但目前与业务运行时注册在一起，需要提取共用实现。

## 宿主与通信

- 主、备机各有独立管理宿主，生命周期与业务服务分开，仅操作本机受控服务。业务未启动、启动失败、数据库不可用或本机为备机时，管理宿主仍可认证并返回本机状态和诊断信息。
- GUI 与 CLI 使用独立配置的本机 HTTPS 管理地址，首批只监听回环地址，使用独立于业务端口的管理端口。端口由部署配置指定，不写死为产品常量，也不开放远程管理监听。
- 管理入口使用 `/management/v1` 路径，由同一应用服务处理 GUI 与 CLI 请求。客户端不得先要求业务 `/health/ready` 或业务考试查询成功，才能进入管理页面或建立管理连接。
- 管理宿主的初始化、身份验证和状态查询不得因加载数据库适配器或业务配置失败而整体退出。依赖缺失应在相应操作或检查结果中报告，不能构造空检查并返回通过。
- 管理通信的证书和凭据通过受保护的本机部署配置提供，不能依赖业务进程下发。管理通信与被诊断的业务证书配置分开加载；客户端校验证书和预期节点身份，不通过关闭证书校验或自动降级 HTTP 恢复连接。管理证书本身不可用时明确报告，并按部署恢复流程处理。

## 身份验证与操作权限

当前 F01 接线复用已有 `Authorization: Bearer`、`ExamSecurity:OperatorToken` 和 `ExamSecurity:OperatorId` 约定。提取共用的令牌验证与已认证操作者上下文，由业务宿主和管理宿主分别注册；共用校验不得依赖 `ActiveNodeGuard`、设备身份服务、业务登录接口或 PostgreSQL。

沿用现有配置校验，令牌由受保护配置提供且至少 32 个字符，OperatorId 必须有效。凭据不得进入普通服务配置、源码、URL、响应或日志。配置缺失、无效或不可读取时拒绝管理访问，不生成默认口令，不因数据库故障切换为匿名模式。

所有管理端点都执行身份验证，包括只读状态和操作结果查询。审计操作者取自验证结果；请求若携带 `actorId`、`operatorId` 或 `operator`，必须与已认证身份一致。校验逻辑共用，客户端不能自行声明身份取得权限。

管理访问成功后，各操作仍须执行自己的条件检查。

| 操作 | 故障或备机状态下的处理 |
| --- | --- |
| 查询本机状态、配置和检查结果 | 数据库不可用或非活动节点不应阻断整个请求；明确返回不可用、未核实或失败的项目 |
| 保存本机配置 | 执行现有停止状态、配置版本、路径和持久保存检查，不返回秘密字段 |
| 停止受控业务服务 | 可以在数据库故障时执行；核对实际服务状态，失败或超时不能报告已停止 |
| 启动业务服务 | 执行启动与恢复检查；关键项失败保持业务写入关闭，进程启动不等于业务就绪 |
| 备份、隔离恢复 | 校验各自依赖、受控路径和操作条件；数据库不可用不等于允许备份成功，隔离暂存完成不等于业务恢复完成 |
| F02 接管与开放业务写入 | 继续执行旧主隔离、副本、资源、身份、角色和代次检查；本决策不授予跳过接管流程的权限 |

现有业务 API 保留活动节点及业务权限检查。提取共用身份校验时不得通过删去原业务门禁完成接线。

本决策使用现有令牌机制衔接 F01，不将其视为考务端用户名和密码注册登录已经完成。后续登录功能仍按需求实现，并与共用身份验证协调，F01 不另建用户注册体系。

## 复用与补充契约

复用 [ServiceManagementContracts](../../src/Exam.Contracts/ServiceManagement/ServiceManagementContracts.cs)中的 `ServiceConfiguration`、`ServiceStatusSnapshot`、`StartupCheckResult`、`BackupRequest`、`BackupResult` 和 `RestoreRequest`。`RestoreResult` 需要结合恢复阶段补充语义，现有类型本身不能表达隔离暂存与业务就绪的区别。

沿用 [公共契约](../../src/Exam.Contracts/Common/ApiContracts.cs)的 `ApiError`、适用错误码及 `MutationContext` 中的请求标识、版本和操作者规则，使用现有 `JsonDefaults`。F 在 `Exam.Contracts` 中补齐下表的管理请求、操作结果和响应封套，并提供合成成功、失败样例。表中路径相对于 `/management/v1`，属于待实现约定。

| 方法与路径 | 输入或用途 | 结果要求 |
| --- | --- | --- |
| `GET /service/status` | 已认证的本机管理请求 | 复用状态与检查类型，分别表示实际进程状态和业务就绪状态 |
| `GET /service/configuration` | 读取本机非秘密配置 | `ServiceConfiguration` 及当前配置版本 |
| `PUT /service/configuration` | `requestId`、`expectedVersion` 和目标配置 | 持久保存后的配置及版本；冲突不覆盖原配置 |
| `POST /service/start`、`POST /service/stop` | `requestId`，并绑定本次目标节点和操作内容 | 操作标识、阶段及实际状态，不能仅凭已发出 SCM 命令报告完成 |
| `POST /service/checks` | `requestId`，发起本机自检 | 检查结果与阻止业务写入的原因；不自动启动或提升节点 |
| `POST /service/backups` | 复用 `BackupRequest`，核对已认证操作者 | 操作阶段及完成后的 `BackupResult` |
| `POST /service/restores` | 复用 `RestoreRequest`，核对已认证操作者 | 分别表达隔离暂存、恢复核对及业务就绪情况，未完成步骤不能省略为成功 |
| `GET /operations/{requestId}` | 查询原请求的处理状态 | 操作类型、阶段、原结果或稳定错误；不存在时明确返回未找到 |

F 可在上述范围内确定具体 C# 类型和共享接口名称，随实现 PR 审查；无需因类型命名再次等待授权。涉及新增操作、扩大管理权限或改变既有业务契约语义时，先提交差异由 A 确认。

### 数据库不可用时的响应身份

现有 `ApiEnvelope<T>` 的 `serverEpoch` 是必填整数，不能直接表达尚未核实的当前代次。新增管理响应封套，保留 `serverId`、`nodeId`、`correlationId`、`result` 和 `error`，使 `serverEpoch` 可为空，并明确代次是否已核实及核实时间。

只能把本次成功读取权威状态所得的代次标为已核实。权威状态不可用时，当前代次为空并标为未核实；如展示历史观察值，使用单独字段及时间，不使用配置值、历史值或 0 冒充当前代次。客户端仍核对预期逻辑服务器和本机节点，未核实的代次不能用于接受业务写入或判断接管成功。

此规则仅适用于独立管理响应，现有业务封套及客户端拒绝错误身份、过期代次的规则不变。管理请求的目标节点、请求内容和已认证操作者在持久操作记录中绑定，防止把一个节点的重试当成另一个节点的操作。

### 重试、进度与恢复

启停、配置保存、自检、备份和恢复请求都携带稳定 `requestId`。配置修改另带 `expectedVersion`。相同请求标识和相同内容返回原操作状态或结果；标识相同但操作、内容或操作者不同则拒绝，不再次执行。

管理宿主在本机受保护目录持久记录操作与审计，存储不依赖正在修复的业务数据库。已有数据库备份记录不能充当离线管理的唯一请求记录。本机记录仅用于管理操作恢复，不替代数据库中的考试、答卷和主备权威状态。

变更操作在产生副作用前记录受理信息；持久记录失败时不执行变更。异步受理返回 HTTP 202 及可查询的请求标识；完成结果持久保存后才报告完成。成功结果用 HTTP 200；输入错误用 400，认证或权限错误用 401/403，版本或请求内容冲突用 409，依赖不可用用 503，沿用 CLI 退出码约定。

管理宿主重启后按原请求核对实际服务、配置及恢复阶段，避免重复执行有副作用的步骤。崩溃发生在副作用完成与结果记录之间时，先核对实际状态；无法确认则返回明确的待核对状态，不能猜测成功或自动重复恢复。记录失败也不能影响只读状态诊断。

A 确认 F 可为上述接线修改 `src/Exam.Application/ServiceManagement`、`src/Exam.Contracts/ServiceManagement`、必要的通用管理契约、`src/Exam.Server` 中的共享身份校验及注册、新管理宿主和对应基础设施与测试。共用身份接口按现有依赖方向放置，GUI/CLI 不复制校验。此授权不包含新增数据库迁移或取消业务权限检查。

后续实现至少验证以下场景。

- 业务停止、启动失败、数据库不可用及备机状态下，有效身份仍可查询本机管理状态；GUI/CLI 不被业务连接检查挡住。
