# 系统契约与数据边界

## 组件与身份

学生端、考务端使用 WPF，共用 `Exam.Desktop.Shared` 的主题与组件。业务服务器提供 HTTP API 和 SignalR 事件，独立服务器管理宿主在业务停止时仍向正式管理API和CLI提供认证、查询和启停。考务 GUI 正常登录后以业务令牌换取管理会话；业务不可用时可从登录页独立登录管理服务并接管，一般启停仍使用 CLI。GUI与CLI共用应用服务、身份和版本校验，GUI不展示代次。部署依赖见各组件说明和 `packaging/layout.json`。

考试、参试进入、设备授权、答题进度、时间、试卷、计分规则和服务器代次分别维护单调版本。重试沿用原请求标识；旧通知和断网不改变已确认状态。新的时间修改按服务器当前时间和完整起止时间重算考试状态，已固定或已提交的答卷保持不变。响应身份必须与可信部署一致。管理会话与业务会话相互独立，操作者由服务端认证结果确定。

## 学生题包

学生显示清单只含考试结构、PDF 映射、显示选项及允许的显示资源，不含参考答案、计分公式或 TeX 源路径。题目、清单和 `option-regions.json` 作为同一试卷版本加密、校验和原子切换；规则修订和题目修订分别处理。格式见[导入规范](import-package-spec.md)、[学生导航](student-navigation.md)和[选项定位](option-region-contract.md)。

包解析在工作线程执行。解析完成后重新核对载荷、授权、服务身份及试卷版本，结束、撤权、关闭会话或换版期间返回的旧结果不能创建新答题会话。未知文件、越界路径、重复 JSON 字段、缺失资源和错版本使整包失败，不用部分资源替换可靠旧版。

## 完整答卷

学生端只在没有既有记录、已取得当前授权并验证题目清单后，为每题建立显式 Empty。修改答案保留其他题目，固定时保存完整快照。恢复时发现缺题、陌生题目或非法选项会停止作答，保留原 SQLite 记录，不补造答案。已固定的旧答卷仍优先恢复和保留，严格计分若发现残缺会报错，不能将其冒充有效分数。

生产 SubmissionService 从 IExamVersioningService 读取已发布的 PaperStructure，在保存新进度和新答卷前执行 AnswerSheetContract。其题目编号、题型、选项和 AllowAbstain 与学生清单来自同一导入映射。AllowAbstain 加入 PaperQuestionStructure，旧序列化数据缺少该字段时取 false；开考后更改这一约定也属于不允许的结构变更。

已经持久保存的答卷继续由原事务存储核对身份和授权，重复请求返回原回执，不覆盖原答案。没有发布清单的新答卷会被拒绝。底层独立存储测试可省略清单读取器，生产注册始终提供；其他新调用点也必须提供清单。

答案、标记、当前题和待提交快照使用 SQLite WAL 与 FULL 同步保存。失焦开始立即持久保存零时长事件并唤醒同步，复焦时以同一事件标识补齐时长；离线、重启和重复投递不增加重复次数。只有身份、试卷版本和事件集合一致的回执才能清理待报记录。

## 发布、计分与报表

`ImportedGradingRules.Create` 联合校验清单、完整独立答案、题组与科目满分，以及全部可达作答分支。正式规则发布重新校验原始输入并核对已发布的试卷，不信任客户端自行声明的验证结果。计分只读冻结答卷，按答卷与规则版本去重；原始答案永不被重算覆盖。

计算使用精确有理数，不以浮点误差补偿或提前舍入代替规则计算。小题负分先累加，单科总分为负才归零，各科互不抵扣。排名和均分使用精确值；均分显示两位。单科及该科小题均分以该科最终分数大于零者为样本；总均分仍以所有科目最终分数均大于零者为样本。班级内分别应用对应筛选。

四人合成核算样例（非真实考生）：1001 为10/20分，1002为0/30分，1003为5/5分，1004为8/2分；总分排名依次为1、1、3、3。甲科及总分样本排除1002，乙科包含四人。科目均分为23/3与57/4，总分均分为50/3，显示7.67、14.25、16.67。详见[计分核算基准](scoring-baseline.md)。

## 运行保护

正式业务服务必须配置 PostgreSQL、节点身份和持久确认，任何环境名称都不启用匿名访问、内存回退或无确认的成功响应。内部状态推进由业务服务与后台任务完成，HTTP 不开放直接设置参试状态、任意创建事件、跳过资源验证的入口。测试注入能力仅存在于受约束的回环测试宿主，不进入运行包。

备份、恢复和人工隔离后的接管通过独立管理宿主操作。健康活动节点自动按本机可靠落盘继续业务，对端恢复后自动补齐复制。恢复先到隔离位置核对完整性，不能用旧备份覆盖更新答卷。接管必须确认旧主隔离，不能仅凭心跳丢失；旧主回归必须重建，不自动合并分叉数据。详见[运行手册](backup-and-failover-runbook.md)。

数据库历史迁移名、已有加密恢复标识和持久事件格式属于兼容性边界，不能为了文字清理而改写。真实试卷、答案、个人资料、口令、证书私钥和连接配置不进入 Git。

时间修改的原因可留空，由当前认证考务账号生成操作者字段。时间、原因、操作者、预期版本、新时间窗及生命周期重算策略在同一不可变版本事件中保存。保存时，当前时间早于开始时间为未开始，达到开始时间但早于结束时间为进行中，达到结束时间为已结束；实际开始记录不限制状态重算。历史事件按其原有策略重放，旧请求重试返回原回执，不以新策略再次执行。
