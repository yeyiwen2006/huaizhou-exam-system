# 学生端可信主备重连

学生端只连接经过验证的登录入口及可信主备节点。重连必须核对节点证书、服务器身份和代次，并保留原参试身份、作答内容和待确认请求。

## 节点配置

支持一个或两个受信节点。单节点配置只列本机，双节点部署同版本服务；在仓库外受保护配置设置 `StudentFailover:Nodes`，每项包含独立 IP、HTTPS 端口、`NodeId` 和证书 DER 的 SHA-256 指纹。节点集合必须与 `HighAvailability:RequiredNodeIds` 一致，且包含本机节点；生产双节点配置缺失时拒绝启动。[示例](../../deploy/student-failover.example.json)只使用合成地址及无效演示指纹，不能原样部署。两侧逻辑 `ServerId` 相同，本机 `NodeId` 不同。

单节点加入第二台时，可通过现有可信连接增加一个新节点，原节点地址、端口、身份和证书信息必须全部保持。拓扑校验、受保护设备存储和连接更新使用同一条扩展规则。服务器暂时只返回已保存节点的子集时，保留原可信集合，不清除原备机或设备登记；缺少某个节点的响应不作为撤销该节点信任的依据。真正更换原节点证书、源地址、身份或撤销已有节点信任，需要独立且明确批准的信任迁移，不能通过重新登录静默替换。

## 登录入口与公网映射

学生每次启动填写服务器地址，默认连接 HTTPS 443，也可填写包含自定义端口的完整 HTTPS 根地址，经 `POST /api/v1/student/login` 直接登录，无需考务批准。登录响应包含设备当天编号与 `topology`，学生端经可信连接核对后保存设备凭据和主备信息。已有设备保留原凭据，服务器按当前日期更新公开编号。主备信任配置可使用 IP 地址或域名。

初次使用 HTTPS 域名登录时，如果该地址未直接列在返回的节点地址中，只有本次连接已通过 Windows 标准证书链和域名校验，且登录响应的节点标识确实属于批准拓扑，才能将用户填写的入口绑定为该节点的访问别名。只绑定本次连接对应的节点，不从响应学习其他公网域名；另一个节点仍使用已经批准的地址。配置证书指纹的直连继续核对原指纹，不以别名转换跳过证书校验。已保存的可信公网映射在后续登录中继续使用，不因服务器返回内网地址或部署文件缺失而清除。

使用公网 HTTPS 代理连接整个主备环境时，在学生端 `server.json` 的 `publicEndpoints` 中预先指定公网域名与原节点的对应关系，配置格式见[学生端部署说明](../../deploy/student/README.md)。客户端先核对逻辑服务器、节点标识和原地址，再使用对应公网地址；公网连接按 Windows 标准证书链和域名校验，原节点直连仍按证书指纹校验。下载描述中的原节点地址可转换为当前已批准的公网入口，未知地址仍被拒绝。节点代次、设备凭据和请求重试规则保持一致。

公网域名更换时，只有本机部署配置明确给出新入口，且逻辑 `ServerId`、节点 `NodeId` 与原节点源地址均能对应原登记，才迁移原设备记录的访问地址。迁移保留设备身份、凭据、当天编号、原节点证书指纹和最高代次，并沿用受保护的原子保存与备份。考试恢复记录按逻辑服务器、设备、考生和考试标识隔离，这些标识不因换址改变，原缓存和待确认答卷继续有效。存在多份无法唯一识别的登记、源地址不符或新地址与其他登记冲突时，保留原记录并拒绝自动替换。

没有可信映射的新域名不能仅凭响应自报的 `ServerId` 自动认领旧设备身份；该地址只能按独立连接建立登记，不向它发送其他地址保存的设备凭据。新增别名和公网域名迁移都不代表批准更换原节点证书。指纹大小写、空格或冒号可以归一化，实际指纹变化仍须通过明确批准的信任迁移处理。

## 故障行为

主备角色切换仅更新受保护设备记录的最高代次及活动节点；原设备存储键、身份、名册、参试授权及本地答卷不变。重启读取已持久化活动节点；旧内存对象不能降低代次或把已确认的主节点改回原主。用户再次输入旧主机地址，也只改变本次尝试连接的目标，不覆盖已经保存的活动节点。HTTP、资源下载与 SignalR 均使用同一设备的可信集合，按目标节点的直连指纹或公网 HTTPS 规则核对证书，不共用其他设备的信任集合。

请求连接失败、超时，或返回非活动、恢复中、过期代次、副本不可用错误时，只探测可信集合内的另一节点。已知旧节点返回较低代次的这些失败状态，可以进入探测流程；较低代次的成功业务响应仍被拒绝。探测不发送设备凭据，原节点直连最多等待 4 秒，公网 HTTPS 入口最多等待 15 秒，并核对 HTTPS 信任、逻辑身份、节点身份及时间响应内外身份。

新的接管节点必须具有更高代次。若本机已经持久保存某节点是当前主机，再次从旧主机连接时，也可回到该已保存节点的同一代次；其他节点不能凭相同代次成为主机。确认后先持久保存活动节点与最高代次，再向该节点重发原请求字节，最多一次。不生成新 `requestId` 或交卷 ID，不替代方案 A 所要求的真实旧主隔离和管理接管。只有一个受信节点时直接使用本机业务连接，不因缺少第二个地址而拒绝登录、下载或交卷。授权被撤销、证书错误、未知身份或旧代次都不能通过重新登记绕过。

通知连接失效时，考试运行实例每 3 秒尝试上述核对并重建通知连接，沿用同一参试登记与授权。健康且身份相同的连接不增加探测。旧连接响应、指令及撤销回调按连接代次丢弃；撤销状态不可由重连解除。节点变化触发服务时间重同步，失败保留既有单调时钟。重连总耗时包含原请求超时和网络探测时间。直连内网仍须在目标双机环境验证服务恢复可用后 10 秒内重新建立连接的要求；公网入口允许更长的探测等待时间，需要单独测量恢复耗时。正常时间请求在直连时最多等待 2 秒，在已配置或已保存的公网入口最多等待 15 秒。

资源地址只允许已保存的可信主备集合及对应源地址。切换后的旧绝对地址改绑至可信活动节点，并保留资源路径、试卷版本和准备登记；中途断线由题包管理器截断本次临时文件并从头下载同一版本，最多重新下载一次，不能拼接两节点数据。已完整安装的旧版本保留至新包完整验证和原子安装完成。

## 恢复与版本回退

排查连接问题时，保留原 DPAPI 设备记录、固定答卷和最高代次。不能清空设备文件或答卷来解决连接问题，也不能在考试期间回退到不支持主备信息的旧版本。

现场验证应分别覆盖主机故障、备用节点接管、旧主重新出现、连续重试、题包下载中断和原交卷回执查询，并检查单节点加入备机、部分拓扑返回、初次 HTTPS 别名、本机批准换址和缺失公网配置时的登录行为。对证书、节点、源地址或逻辑身份不符的响应，确认原登记保留且不会向未批准的入口发送旧凭据。检查重连后的编号、参试授权、题目版本和答卷是否保持一致；单机回环或短时合成测试不能替代双机整场验证。
