# 学生端可信主备重连

学生端只连接部署时批准的主备节点。重连必须核对节点证书、服务器身份和代次，并保留原参试身份、作答内容和待确认请求。

## 节点配置

支持一个或两个受信节点。单节点配置只列本机，双节点部署同版本服务；在仓库外受保护配置设置 `StudentFailover:Nodes`，每项包含独立 IP、HTTPS 端口、`NodeId` 和证书 DER 的 SHA-256 指纹。节点集合必须与 `HighAvailability:RequiredNodeIds` 一致，且包含本机节点；生产双节点配置缺失时拒绝启动。[示例](../../deploy/student-failover.example.json)只使用合成地址及无效演示指纹，不能原样部署。两侧逻辑 `ServerId` 相同，本机 `NodeId` 不同。单节点加入第二台时，只允许通过现有可信连接增加一个新节点，原节点地址、端口、身份和证书信息必须全部保持。更换已有地址/证书或移除已有节点需要独立信任迁移，不能静默替换。

学生每次启动填写服务器地址，默认连接 HTTPS 443，也可填写包含自定义端口的完整 HTTPS 根地址，经 `POST /api/v1/student/login` 直接登录，无需考务批准。登录响应包含设备当天编号与 `topology`，学生端经可信连接核对后保存设备凭据和主备信息。已有设备保留原凭据，服务器按当前日期更新公开编号。主备信任配置可使用 IP 地址或域名，登录输入应与部署的可信节点地址一致。

主备切换仅更新受保护设备记录的最高代次及活动节点；原存储键、身份、名册、参试授权及本地答卷不变。重启读取已持久化活动节点；旧内存对象不能降低代次或把连接切回原主。原节点证书仍按部署时确认的信任信息校验；取得集合后，HTTP、资源下载与 SignalR 均按目标 IP 对应证书精确核对，不共用其他设备的信任集合。

使用公网 HTTPS 代理时，在学生端 `server.json` 的 `publicEndpoints` 中预先指定公网域名与原节点的对应关系，配置格式见[学生端部署说明](../../deploy/student/README.md)。客户端先核对逻辑服务器、节点标识和原地址，再使用对应公网地址；公网连接按 Windows 标准证书链和域名校验，原节点直连仍按证书指纹校验。下载描述中的原节点地址可转换为当前已批准的公网入口，未知地址仍被拒绝。节点代次、设备凭据和请求重试规则保持一致。

## 故障行为

请求连接失败/超时，或返回既有非活动/恢复/过期代次/副本不可用错误时，只探测可信集合内的另一节点。探测不发送设备凭据，原节点直连最多等待 4 秒，已配置的公网 HTTPS 入口最多等待 15 秒；要求对应 HTTPS 信任校验、逻辑身份、节点身份、时间响应内外身份一致，且代次严格增加。先持久保存新代次，再向新主重发原请求字节，最多一次。不生成新 `requestId`/交卷 ID，不替代方案 A 所要求的真实旧主隔离和管理接管。只有一个受信节点时直接使用本机业务连接，不因缺少第二个地址而拒绝登录、下载或交卷。授权被撤销、证书错误、未知身份或旧代次不触发重新登记。

通知连接失效时，考试运行实例每 3 秒尝试上述核对并重建通知连接，沿用同一参试登记与授权。健康且身份相同的连接不增加探测。旧连接响应、指令及撤销回调按连接代次丢弃；撤销状态不可由重连解除。节点变化触发服务时间重同步，失败保留既有单调时钟。重连总耗时包含原请求超时和网络探测时间。直连内网仍须在目标双机环境验证服务恢复可用后 10 秒内重新建立连接的要求；公网入口允许更长的探测等待时间，需要单独测量恢复耗时。正常时间请求在直连时最多等待 2 秒，在已配置的公网入口最多等待 15 秒。

资源地址只允许原主备集合。切换后的旧绝对地址改绑至可信活动节点，并保留资源路径、试卷版本和准备登记；中途断线由题包管理器截断本次临时文件并从头下载同一版本，最多重新下载一次，不能拼接两节点数据。已完整安装的旧版本保留至新包完整验证和原子安装完成。

## 恢复与版本回退

排查连接问题时，保留原 DPAPI 设备记录、固定答卷和最高代次。不能清空设备文件或答卷来解决连接问题，也不能在考试期间回退到不支持主备信息的旧版本。

现场验证应分别覆盖主机故障、备用节点接管、证书不符、旧主重新出现、题包下载中断和原交卷回执查询。检查重连后的编号、参试授权、题目版本和答卷是否保持一致；单机回环或短时合成测试不能替代双机整场验证。
