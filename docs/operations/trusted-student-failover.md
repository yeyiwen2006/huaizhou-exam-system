# F03 学生端可信主备重连

关联 #16；按 requirements.md「激活」「主备服务器与接管」「真实考试的可靠性要求」实现。关键契约、身份及恢复变更交 A 审查，不能据此关闭 T01/T02 或宣称双机验收通过。

## 配置与接线

两节点部署同版本服务；在仓库外受保护配置设置 `StudentFailover:Nodes`，每项包含独立 IP、HTTPS 端口、`NodeId` 和证书 DER 的 SHA-256 指纹。节点集合必须与 `HighAvailability:RequiredNodeIds` 一致，且包含本机节点；生产双节点配置缺失时拒绝启动。[示例](../../deploy/student-failover.example.json)只使用合成地址及无效演示指纹，不能原样部署。两侧逻辑 `ServerId` 相同，本机 `NodeId` 不同。更换地址/证书需要独立信任迁移，当前实现拒绝静默替换已批准集合。

激活批准及重新激活响应附加 `topology`；学生端经原可信连接核对后，与编号/凭据一起保存到既有 DPAPI 设备文件。原设备没有主备信息时，经携带原凭据的 `GET /api/v1/student/server-topology` 补取，不重新激活、不换编号。接口仍经过活动节点、恢复及设备认证门禁；未配置时返回可重试错误。补取失败保留设备文件并阻止登录，不能猜测备用地址。旧版服务不提供该接口时，需要先升级部署并完成信任配置。

主备切换仅更新受保护设备记录的最高代次及活动节点；原存储键、身份、名册、参试授权及本地答卷不变。重启读取已持久化活动节点；旧内存对象不能降低代次或把连接切回原主。原节点证书仍按 B07 校验；取得集合后，HTTP、资源下载与 SignalR 均按目标 IP 对应证书精确核对，不共用其他设备的信任集合。

## 故障行为

请求连接失败/超时，或返回既有非活动/恢复/过期代次/副本不可用错误时，只探测批准集合内的另一节点。探测不发送设备凭据，最长 4 秒；要求 HTTPS 指纹、逻辑身份、节点身份、时间响应内外身份一致，且代次严格增加。先持久保存新代次，再向新主重发原请求字节，最多一次。不生成新 `requestId`/交卷 ID，不替代 F02 隔离、提升或应急授权。授权被撤销、证书错误、未知身份或旧代次不触发重新激活。

通知连接失效时，考试运行实例每 3 秒尝试上述核对并重建通知连接，沿用同一参试登记与授权。健康且身份相同的连接不增加探测。旧连接响应、指令及撤销回调按连接代次丢弃；撤销状态不可由重连解除。节点变化触发服务时间重同步，失败保留既有单调时钟。真实恢复总耗时受原请求超时及网络影响，尚未证明 T02 的服务可用后 10 秒指标。

资源地址只允许原主备集合。切换后的旧绝对地址改绑至可信活动节点，并保留资源路径、试卷版本和准备登记；中途断线由题包管理器截断本次临时文件并从头下载同一版本，最多重新下载一次，不能拼接两节点数据。已完整安装的旧版本保留至新包完整验证和原子安装完成。
