# 首轮任务、依赖与联调顺序

## 启动批次

第一批先合并 A01 公共契约与工程骨架、D01 逐题包规范和 E01 自动检查入口。B01、C01、C02、C03 可以基于公共样例并行，但接口字段变化必须先更新契约和样例。

第二批由 A03、A04、D02、D03 接通进入考试、可靠指令和加密试题服务，再联调 B02、B03。A08、B08、C07 同期制作最小主备原型，但没有双机演练记录时不能标记 M1 通过。

第三批连接 A05、B04、B05、D04、E02、E03，跑通本地保存、进度同步、唯一最终答卷、计分、统计和导出，形成 M2 小规模闭环。

第四批连接 C05、A06、B06、D05，完成时间、题包和计分规则在线修订及整体重算。E04 从 M2 起记录集成和故障验证，E05 至 E07 在固定候选提交上执行负载、部署及双机恢复。

## 审查安排

- A 组代码由 B 核对客户端时序，E 复核并发、持久化与恢复。
- B 组代码由 C 检查交互，A 审查授权和数据一致性。
- C 组代码由 B 检查交互，D 核对计分配置，E 核对报表。
- D 组代码由 B 核对版式，A 审查执行边界，E 独立核算。
- E 组代码由 D 核对数值，C 核对展示导出，A 审查服务调用。

授权、交卷、主备、计分、密钥和数据库迁移属于关键变更，除上述非作者审查外还需 A 确认。A 自己的代码不能自审代替非作者复核。

## 阶段检查

每个阶段只依据固定提交的实际记录作结论。记录至少包含环境、输入、预期、实际、提交哈希、未执行项、缺陷和复测状态。单元测试、模拟存储或 300 个进程会话分别只证明对应范围，不替代真实数据库、双机、普通账户、场地网络和真实设备验证。
