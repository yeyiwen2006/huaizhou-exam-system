# 开发期模块测试与两轮项目整体测试

本安排不替代[执行指南](../agent-implementation-guide.md)的S01—S21及性能指标。开发期间持续进行模块测试；只有把全部模块合起来的项目正式测试后置到全部代码完成后。T01、T02各自包括测试执行、问题修复、复测和回归，不另设测试后修复总单。

## 测试责任

A安排整体测试、确认准入和最终结论，并负责所有PR的代码审查与合并。A—F全员执行项目测试，每位成员均跑共同基础流程；专项另分工。E搭建并维护CI、隔离环境、合成数据、故障注入、负载、结果核对和记录工具，并汇总记录，不独自承担全部测试。F提供产品的主备部署、监测、接管和恢复能力及工具；实际整体演练归T02。

开发期每个作者须执行本模块适用的单元、接口、数据库/文件持久化、GUI、并发、故障与恢复测试；接口接通后立即做模块边界集成，修复后回归并通过相关CI。测试设施本身同样要有模块测试。环境缺失写清未执行范围，不把未运行、模拟存储或静态样例当成真实集成通过。

## T01 全项目单机测试与缺陷修复（#33）

### 准入

全部计划软件功能、真实GUI/API/CLI接线及部署/测试工具已完成；对应模块检查通过并经A审查合并；E01设施就绪；E04已经从同一候选提交产出运行包。这里要求的是开发子项完成，不是所有含最终验收的Issue关闭，也不是E04最终交付关闭。

### 全员共同流程与专项

A—F每个人使用同一候选提交及配套运行包，运行部署启动、配置考试、名册及试题导入、激活登录、等待作答、保存恢复、交卷、计分重算、统计导出的完整项目流程，并分别登记执行人、环境与结果。可使用各自独立单机环境；不能只测试自己负责的界面。

| 成员 | 在共同流程之外重点执行 |
| --- | --- |
| A | 服务器核心、身份权限、事务/幂等、版本和终态；统筹故障及数据正确性核对 |
| B | 真实题目交互、本地SQLite、答案/标记/当前题恢复、普通账户、分辨率和缩放 |
| C | 配置名册与试场、审批裁决、监测、修改发布、GUI/CLI业务一致性 |
| D | 真实材料与合成结构、编译定位、三题型、精确计分、规则重算及人工基准 |
| E | 统计样本、排序排名、Excel、覆盖记录工具及本机负载回归 |
| F | 管理宿主、启动自检、隔离备份恢复、重试/接管模块中断、主备运维工具及管理入口 |

两轮均复用既有用例，不修改其预期结果或降低性能标准。每个场景的细节以执行指南为准。

| 既有场景 | T01安排 | T02安排 |
| --- | --- | --- |
| S01—S03 编号试场、名册参试、选项标记 | 真实服务/数据库/GUI完整执行，必要时同机合成多会话 | 复核真实设备、跨机身份和现场交互 |
| S04—S06 交卷回执、多端裁决、时间通知 | 同机隔离多进程及真实持久化，覆盖故障/竞争/重试 | 真实跨机通信、断连、丢包和裁决，复核关键时序 |
| S07—S09 加密恢复、内容和时间修订 | 真实包与客户端，进程中断及原子切换等完整执行 | 跨机解锁、发布与重连、多设备更新 |
| S10—S12 监测回收、重算、GUI/CLI | 完整业务和两种入口核对，包括版本与开放门槛 | 跨机实时监测、补收、整体结果与管理入口复核 |
| S13—S15 不同结构、原版显示、计分报表 | 三校本地材料与不同结构合成包，逐题和人工基准核对 | 真实题包分发、显示和最终结果复核，容量使用实际规模包 |
| S16—S17 Windows发布恢复、GUI一致性 | 普通账户、自包含包、新环境、服务停止后管理启动及共享样式 | 真实独立主机、备用考务入口与目标设备配置 |
| S18 存储与资源故障 | 隔离数据库/目录中真实不可写、写满、资源中断等 | 真实主备/网络条件下相关故障与恢复 |
| S19 断电与现场恢复 | 隔离虚拟机强制断电/重启，记录服务与客户端恢复时间；进程终止不能代替断电 | 目标多机部署的集中重连、恢复及剩余收卷，补齐依赖独立主机的项 |
| S20—S21 主备接管、备机故障与旧主回归 | 仅做模块或同机模拟预检，不记录为真实跨机通过 | 全部正式执行并留证据 |

T01可复用已有本机300会话工具与历史基线进行回归，但回环、单数据库、合成资源、短时运行只证明相应范围，不能替代T02容量结论。无法在单机环境证明的场景明确列入T02；T01本应完成的必测内容不能借此跳过。

### 修复与退出

发现问题立即登记具体bug，关联T01及Sxx，指定模块修复主责。作者修复并做模块回归，A审查最新提交并合并，安排非修复作者执行结果复测；运行复测不是新增代码审查岗位。失败保持打开，成功补证据后关闭。T01只在适用必测项通过、P0/P1及阻塞多机问题清零后由A确认，随后固定T02候选提交和运行包。

## T02 多机联调联试与缺陷修复（#34）

### 准入及环境

T01通过且对应修复回归完成；使用固定候选提交和相同版本运行包；E01基于F05产品工具准备隔离环境。至少两台独立Windows主备服务器、一台独立负载机及两台真实学生设备，主备均有考务端；实际设备规模、系统、网络、硬件、证书与资源配置据实记录。两台学生设备仅为功能联试最低配置，绝不意味着300台真实设备验收已经满足。

### 同一轮正式联试

全员按A安排执行跨机完整考试、上表对应复核、全部S20/S21、全新部署和历史备份恢复。同步副本接管与历史备份恢复分别验证；旧主隔离不以心跳丢失替代，主备使用同一套程序，不自动合并分叉数据。

正常性能验收开启同步复制，由独立负载机经局域网访问。覆盖300独立会话、完整答题状态、最大实际编译题包、首批最长考试完整时长、集中下载/指令/交卷、监测与导出并行、考试中更新、补收重算及300会话接管。逐项采用执行指南原指标，不缩小材料或延长阈值；应急单机单列，不能替代正常双机指标。

F重点执行主备控制和恢复操作，B核对真实学生端重连，C核对考务入口与监测，D核对题包/规则和结果，E运行负载/证据工具，A组织并核对数据一致性。真实设备与模拟会话的结果分别报告；未验证的网络和设备规模不写成通过。

### 修复、回归与放行

本卡直接跟踪联试问题、模块修复、A代码审查与合并、复测及相关回归。“一轮正式联试”不限制必要的重复执行；跨机或接管问题修复后必须在相应真实环境复测，必要时重跑核心考试流程。不把同机测试结果替代多机修复证据。

全部必测功能与性能标准满足、已确认数据无损、P0/P1和阻塞缺陷清零后，A确认T02通过。60秒接管从确认旧主隔离并发起操作计时，客户端10秒恢复从服务可用计时，人工发现/隔离耗时另记。最终由E04汇总A确认的固定版本；测试后有代码或配置变化，必须评估并完成对应回归再交付。

## 记录与缺陷规则

每条用例记录任务/场景、候选提交、运行包版本、测试环境、输入、预期、实际、执行人、证据、失败原因和复测。状态区分未执行、通过、失败、阻塞；所有T01/T02清单初始保持未执行，历史基线不可自动勾选为本轮通过。

具体bug使用发现轮次（开发期模块测试、T01或T02）、模块标签、严重度、修复主责、复测人及关联PR。修复PR合并后进入待复测，不自动关闭bug；重复问题沿用原单并追加复现。严重度P0/P1问题不通过改标签绕过门槛，P2也要明确影响和处理安排由A确认。

T01/T02是唯二整体测试总单，不另建修复总单。工具开发、测试环境及报告设施仍归E01；正式测试执行、发现问题、修复和复测的结果归对应T任务。原有测试、审查和负载记录保留其日期及实际边界，不改写为新版本已通过。
