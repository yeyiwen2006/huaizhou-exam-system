# 系统测试与发布核对

测试按[验收标准](acceptance-criteria.md)执行。单元测试和静态检查是准备工作，不能代替完整考试、真实双机、断电及现场容量验收。各轮使用固定提交及对应运行包，发现缺陷后修复、复测并回归受影响流程，不降低既有预期和性能阈值。

## 单机完整流程

在隔离环境完成部署启动、考试配置、名册与试题导入、激活登录、等待作答、保存恢复、交卷、计分重算和五类统计导出。测试人员执行完整流程，不只测试某个页面。GUI、CLI、数据库和实际文件分别核对。

| 范围 | 检查内容 |
| --- | --- |
| S01—S03 | 编号与试场、名册和实际参试人数、选项与私人标记 |
| S04—S06 | 固定交卷快照、丢回执重试、设备裁决、版本与结束竞争 |
| S07—S09 | 加密解锁、本地恢复、原子试题更新、时间修改与终态保护 |
| S10—S12 | 权威监测、补收、全量重算、GUI/CLI 一致性及通知 |
| S13—S15 | 不同结构合成题包、三校本地材料逐题版式、精确计分与五表人工核对 |
| S16—S17 | 普通账户运行发布包、恢复与独立管理、分辨率及100%/125%/150%缩放 |
| S18—S19 | 真实存储失败和资源中断；隔离虚拟机强制断电及重启，不以结束进程代替断电 |
| S20—S21 | 可做同机模块预检，不能记录为真实跨机接管通过 |

真实材料在私有位置使用；仓库只保留合成样例和不含个人信息的记录。本机300会话工具用于回归，回环、单数据库、短时运行和合成资源不能代替正式多机容量结论。

适用必测项通过，严重及阻塞问题清零后固定下一轮候选提交与运行包。失败项保留复现输入、预期、实际与原始失败证据；修复后由非修复者复测。

## 多机联调与现场验收

至少两台独立 Windows 主备服务器、一台独立负载机及两台真实学生设备；主备均安装考务端。两台学生设备只是功能联试最低配置，不代表300台设备已经验证。记录网络、硬件、账户权限、证书、依赖及题包规模。

用同一候选版本执行跨机完整考试、S20/S21、全新部署和历史备份恢复。正常性能测试保持同步复制开启，经局域网访问，使用300独立会话、完整答案状态、最大实际题包和最长考试完整时长，同时运行考务监测、更新和导出。应急单机另测，不代替正常双机指标。

旧主隔离必须有明确证据，不能用心跳超时替代。分别验证同步副本接管和历史备份恢复；核对故障前已确认数据、未决请求补传、唯一最终答卷、最新计分规则和五表版本。接管60秒从确认隔离并发起操作计时，客户端恢复10秒从服务可用计时，人工发现及隔离耗时另记。

跨机问题修复后在相应真实环境复测，必要时重跑完整考试。所有必测功能、性能、数据无损和严重缺陷门槛满足后才可放行。模拟会话、真实设备、现场网络和断电演练分别给出结论。

## 发布核对

核对已验收提交、发布标签、五个组件运行包、配置模板、依赖清单、导入规范、运维说明、合成样包及测试记录。清单与程序版本必须一致，明确运行限制和恢复路径。此步骤不增加第三轮测试；代码、配置、依赖或打包变化时，先完成受影响范围的回归。

每条记录包含场景、提交、运行包版本、环境、输入、预期、实际、执行人、证据及复测。状态区分未执行、通过、失败和阻塞；历史结果不能自动标记新版本通过。命令与报告入口见[测试工具](test-infrastructure.md)。
