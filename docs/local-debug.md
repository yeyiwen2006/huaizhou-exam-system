# 本机调试与两个目录的代码同步

在 `exam-system-test` 中双击根目录的 `start-local.cmd`。启动窗口会编译调试后台、考务端和学生端，自动查找 PostgreSQL 18，准备独立数据库并启动后台。后台就绪后打开考务端，服务器地址自动填好。

首次使用在考务端注册账号，然后创建考试、导入试题和考生名单。在启动窗口输入 `S` 并回车即可打开学生端。学生端已经配置好服务器地址和证书信任，按正常业务流程申请激活，在考务端批准后继续。激活后的调试学生端同样使用全屏和快捷键拦截，禁止通过 Win、Alt+Tab、Ctrl+Alt+Esc 等组合键切出。需要操作同机考务端时，先通过学生端的“退出系统”入口退出，再在启动窗口打开考务端。调试标记只在 Debug 构建中接受。

输入 `A` 打开考务端，输入 `S` 打开学生端，输入 `Q` 停止本次调试，也可以按 Ctrl+C。停止只处理本次入口创建的进程。数据库、账号、考试、已保存答卷和激活信息会保留，下次启动继续使用。

## 数据保存位置

每个项目目录有自己的 `.artifacts/local-debug`，包含 PostgreSQL 数据目录、证书、连接配置、运行日志、客户端运行副本、`student-data` 学生端记录和 `admin-data` 考务端管理记录。入口通过子进程配置让调试客户端使用各自的独立目录，不读取普通运行时保存的管理连接设置。导出表格和取回源材料的默认位置为其中的 `exports` 子目录，避免混用普通考试记录。初次启动不会预填考试、账号或试题。

考务端通过本机 HTTP 连接，学生端通过 HTTPS 和指定证书连接。入口不会安装系统根证书或关闭客户端的证书验证。默认考务端口为 5089，学生端 HTTPS 端口为 5001。首次创建时端口被占用会选择空闲端口并显示实际地址。已有环境保留原地址；端口被其他程序占用时会启动失败。

学生端要求两个可信节点，所以入口在 `127.0.0.1` 和 `127.0.0.2` 启动两个有独立身份和证书的调试端点。它们共用一个本机数据库，业务接口、数据库适配器及后台任务复用现有实现。此入口用于建考、激活、试题发布、作答、交卷和成绩等业务调试，不能用于主备复制、接管或独立服务管理验收。正式 `Exam.Server` 的部署要求没有放宽。

调试考务端的“本机服务管理”会明确提示尚未部署独立管理服务，管理登录和连接配置入口不可用。后台启停继续使用调试启动窗口；正式部署的首次管理连接配置见 [本机服务管理](service-management.md#首次部署连接配置)。

运行依赖为 Windows、`global.json` 指定的 .NET 10 SDK、Python 3.13 和 PostgreSQL 18。真实试题编译还需要 XeLaTeX。数据库工具默认从 PATH 或 `C:\Program Files\PostgreSQL\18\bin` 查找。可在 PowerShell 中明确指定位置。

```powershell
python -X utf8 eng/development/start_local.py --postgres-bin "C:\Program Files\PostgreSQL\18\bin"
```

修改代码后，关闭调试启动窗口并重新运行入口。没有修改代码时可加 `--no-build` 复用本目录已有的 Debug 构建。`--check` 只启动数据库和后台，确认就绪后停止，不打开客户端。

## 手动同步代码

在任意一边双击根目录的 `sync-code.cmd`，默认同步同级的 `exam-system` 与 `exam-system-test`。在 PowerShell 中执行下面的命令，可以先查看待同步文件。

```powershell
python -X utf8 eng/development/sync_code.py --check
python -X utf8 eng/development/sync_code.py
```

同步范围包含已跟踪的项目文件，以及公共项目目录中新建的源代码、脚本和说明。新建的普通 JSON、PDF、表格、数据库、证书或日志不会因放入源码目录而自动加入同步。任意层级的 `机考单题文件`、`机考答案文件`、`.artifacts`、`artifacts`、`bin`、`obj`、私有材料目录，以及本地配置始终排除，即使误加入 Git 跟踪也不参与文件夹同步。两组试题目录还加入了 `.gitignore`，普通 `git add .` 不会收录它们。真实试题及答案应保存在这些私有目录中；放入公共源码或说明文件的内容会随该文件同步。

同步按上一次同步时的文件内容识别改动。一边修改、另一边未修改时更新另一边；两边改动后内容相同则接受；两边把同一文件改成不同内容时，整次同步停止并列出冲突。代码删除也参与同步；另一边仍是原版本时，删除会传播并先备份原文件，另一边已经修改则报告冲突。Windows 长路径和中文文件名可正常处理。

同步记录及被替换文件的备份位于测试目录的 `.artifacts/folder-sync`。保留这个目录才能继续识别两边各自的改动。遇到冲突时，先比较并合并两边内容，再执行同步。首次同步根据两边共同的已提交文件内容识别已有改动，没有共同基准的不同文件会保留并报告冲突。

两边的 `.git`、分支、提交、远端设置和构建产物各自保留。同步入口不会执行提交、推送或上传。程序改动会同步到原开发目录，运行产生的测试数据继续留在测试副本。正常运行时数据不会跟随同步进入原开发目录或远端；手动强制加入忽略文件、另行整目录上传或另改同步规则属于入口之外的操作。
