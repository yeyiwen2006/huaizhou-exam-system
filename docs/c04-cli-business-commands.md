# C04 CLI 业务命令与监测事件订阅（2026-10-06）

按 `agent-implementation-guide.md:49`（考务入口须覆盖**激活撤销、编号查询与试场管理、监测裁决、指令补发、回收**，
并提供**监测事件订阅**）补齐 C 侧 CLI 的业务命令，并把监测事件从「只有回收」扩展到**回收／冲突／失败**三类。

## 新增业务命令

| 命令 | 说明 | 关键点 |
| --- | --- | --- |
| `activation pending` | 列出待审批的激活申请 | 输出含申请标识、设备、学生端编号与申请时间 |
| `activation approve 学生端编号 [试场名称]` | 批准激活并分到试场（默认未分组） | 按**学生端编号**在待审批列表里解析申请标识；试场按名称解析成试场标识；不要求手填内部标识 |
| `activation revoke 学生端编号 --input FILE` | 撤回激活 | 请求体给出 `reason`；设备标识由**学生端编号**经设备目录解析 |
| `decisions keep 考试名称 学生端编号 --input FILE` | 设备冲突裁决 | 请求体给出 `device`（保留的学生端编号）与 `reason`；内部设备标识与参试版本由监测快照解析；操作者取**登录身份**（`/operators/me`），不接受自填 |
| `commands resend 考试名称 学生端编号 start\|end` | 重发该考生仍可重发的开始或结束指令 | 只挑当前 `CanResend` 的指令；请求体带进入版本、目标设备与授权版本 |
| `commands reupload 考试名称 学生端编号` | 请求补传原答卷 | 对尚未回收的考生重发其结束指令；已回收的考生直接拒绝（退出码 2） |

约定沿用 C 家族既有做法：**考试与试场按名称**、**设备按学生端编号**，参数尽量走位置参数
（CLI 选项解析器只认 `--server`/`--input`/`--request-id`，属 E01 框架，不擅自扩选项）。

## 监测事件订阅

新增 `monitor events <考试名称> [起始名单版本] [间隔秒] [轮数]`：一次订阅同时发出三类事件
（给了间隔秒就持续订阅，默认单次读取后退出）。**stdout 一行一个 JSON**，可读提醒写 stderr：

- `collection`：答卷全部收齐（沿用原有名单版本游标，每个名单版本一次、零参试不触发）；
- `conflict`：**设备冲突待裁决**——同一考生多台设备进入；按「参试记录 + 涉事设备集合」去重，
  冲突消失后再出现会重新通知；
- `failure`：**状态失败**——试题包下载失败或修订未安装；按「参试记录 + 失败种类」去重。

事件明细只用**公开编号与试场名称**，不透出内部设备标识。`monitor watch`/`monitor follow` 保持只发收齐事件
（不依赖监测快照，服务端只需提供收齐接口即可用）；`monitor show`/`monitor missing` 仍是一次性查询。

## 模块验证

- 单元用例（`MonitorEventWatchTests`，5 项）：新增冲突与失败各通知一次、状态不变不重复、冲突消失后再出现重新通知、
  设备集合变化算新冲突、明细只用公开编号、下载失败与修订未安装合并成一条。
- 真 CLI 端到端（`AdministrationCliTests`，新增 4 项）：批准/撤回按编号解析并核对请求体字段、
  裁决保留指定设备且操作者取登录身份、重发与补传挑中可重发指令并核对请求路径与版本、
  已回收考生补传被拒绝；`monitor events` 同时发出冲突与失败事件。
- 用法错误（`CliBoundaryTests`，新增 1 项 8 例）：缺参数、参数过多、非法指令类型一律退出码 2 且**不向服务器发任何请求**。
